### 为什么网页读起来更连贯

网页先建立“多人共用一条信道”的问题，再按协议演化顺序讲：

```text
随时发：ALOHA
  -> 冲突太多

发送前先听：CSMA
  -> 传播时延仍可能造成冲突

有线中边发边听：CSMA/CD
  -> 检测冲突后停止并退避

无线中无法边发边听：CSMA/CA
  -> 通过等待、退避、ACK、RTS/CTS尽量避免冲突
```

这是一条很好的**协议演化线**。王道把基础 ALOHA、CSMA 放在 3.5，把具体的 CD、CA 放在以太网和 WLAN 中，更符合考纲分类，但第一次学时容易觉得内容被拆开了。

## 网页讲得比王道更好理解的地方

### 1. 共享介质模型很直观

网页用“一人发，全网听；但只认目的地址”概括共享介质，适合建立最初模型。

做题时看到这些词，应立即切换到共享信道模型：

```text
CSMA/CD
冲突
传播时延
争用期
最短帧长
集线器
半双工
```

不过还要补一句：现代交换式全双工以太网不是共享介质，不会发生冲突，也不使用 CSMA/CD。

### 2. 协议演化关系更清晰

网页把 `ALOHA -> CSMA -> CSMA/CD、CSMA/CA` 连续讲解，能解释每个新机制是在修补什么问题。

建议把这条线作为理解主线，不要割裂背诵四个协议。

### 3. 区分传播时延和发送时延

```text
传播时延 = 距离 / 信号传播速度
发送时延 = 数据量 / 数据传输速率
```

CSMA/CD 的最短帧问题正是把二者联系起来：

$$
\frac{L_{min}}R\ge2\tau
$$

网页从碰撞返回过程解释公式，比直接背 `Lmin=2τR` 更容易长期记住。

### 4. CSMA/CA 时序适合画图理解

```text
DIFS -> RTS -> SIFS -> CTS -> SIFS -> DATA -> SIFS -> ACK
```

网页用隐藏站、NAV 和 RTS/CTS 串起整个过程，很适合应对 2020、2024 等时序题。

### 5. 802.11 三地址口令很好用

```text
地址1：当前无线跳谁接收
地址2：当前无线跳谁发送
地址3：保留原始源或最终目的
```

这比直接死背表格更稳。之后再根据 `To DS` 和 `From DS` 填具体地址。

## 王道需要补回来的内容

网页适合快速理解，但不能完全替代王道。以下内容在网页中较弱或缺失。

### 1. MAC 方法应有三大类

完整框架是：

```text
介质访问控制
  -> 信道划分：静态分配
  -> 随机访问：动态争用
  -> 轮询访问：动态、受控访问
```

网页总结时主要列了信道划分和随机访问，弱化了轮询访问及令牌传递。统考框架题中要记三类。

### 2. IEEE 802 的 LLC/MAC 分层

王道 3.6.1 还要求：

- IEEE 802 对应 OSI 的物理层和数据链路层。
- 数据链路层进一步分为 LLC 和 MAC 子层。
- MAC 负责与传输介质相关的介质访问、成帧和差错检测。
- LLC 与具体介质关系较小。

网页虽单独讲 MAC，却没有把它放回 IEEE 802 的完整层次中。

### 3. 以太网的服务性质

统考高频结论：

```text
无连接、不可靠、尽最大努力交付
不编号、不确认、不负责重传
```

网页重点在帧格式，王道则明确考查 MAC 服务性质。2012 年统考题直接考过。

### 4. CSMA/CD 的考试数字

除了理解原理，还要记住：

```text
经典争用期：51.2μs
经典最短帧：512bit=64B
k=min(冲突次数,10)
第16次冲突后放弃
干扰信号：32bit或48bit
帧间最小间隔：96bit time
```

网页讲了主要公式和退避过程，但真题还会围绕设备时延、最大距离和第 11 次冲突设陷阱。

### 5. 无线局域网的组织结构

网页主要讲 CSMA/CA 和帧地址，王道还要求：

- BSS、BSA、AP、SSID
- DS、ESS、Portal
- 有基础设施网络与 Ad Hoc 网络
- DCF 必须实现，PCF 可选
- 漫游的基本概念

这些多为选择题概念，不能只学 RTS/CTS。

### 6. 高速以太网

王道还区分：

| 类型 | 半双工 | 全双工 | CSMA/CD |
| --- | --- | --- | --- |
| 100Base-T | 支持 | 支持 | 半双工时使用 |
| 吉比特以太网 | 支持但少见 | 支持 | 半双工时使用 |
| 10吉比特以太网 | 不支持 | 仅全双工 | 不使用 |

网页没有系统整理这一块。

### 7. VLAN 链路和帧长细节

王道做题还需要：

```text
Access：主机到交换机，通常无标签
Trunk：交换机之间，通常带802.1Q标签
最大帧长：1518+4=1522B
最小帧仍可为64B
带标签时最小数据字段为42B
标签变化后FCS重新计算
跨VLAN通信需要路由器或三层交换机
```

## 网页中需要纠正或谨慎记忆的表述

### 1. VLAN 标准不是 IEEE 802.3c

网页写道：

```text
“802.3c标准定义了支持VLAN的以太网帧格式扩展”
```

这应改为：

```text
IEEE 802.1Q 定义VLAN标记及相关桥接机制
```

网页后面称其为“802.1Q 帧”是正确的，前面的 `802.3c` 可视为明显笔误。

> [!danger] 应试口径
> 看到 VLAN 标签、4B 标签、Trunk，认准 `IEEE 802.1Q`。

### 2. 1518B 不是 MTU

网页把“最大以太网帧 1518B”又称为 MTU，这不严谨。

```text
标准以太网帧最大长度：1518B
以太网数据字段最大长度：1500B
通常所说的以太网MTU：1500B
```

MTU 指链路层一次可承载的最大网络层数据报大小，通常对应数据字段上限，不包含 14B MAC 首部和 4B FCS。

### 3. 以太网填充不应记成“读取 IP 首部后填充”

网页说以太网设备读取 IP 首部长度后决定填充，这种说法过于特化。

更稳的理解是：

```text
MAC层发现有效载荷不足46B
  -> 在帧的数据字段后补齐
  -> 使MAC帧达到最短64B
```

以太网还可承载 ARP、IPv6 等多种上层协议，填充规则不是只为 IPv4 设计。

### 4. 802.11 地址4不是“用于自组网络”

网页将地址4概括为用于 Ad Hoc，这容易记错。

更准确的考试理解是：

- 普通基础设施模式通常使用地址1、2、3。
- 当 `To DS=1` 且 `From DS=1` 时，帧在无线分布系统中转发，需要地址4。
- Ad Hoc/IBSS 通常不是地址4出现的理由。

统考现阶段主要考前三个地址，但不要把“地址4 = 自组网络”背下来。

### 5. RTS/CTS 是缓解隐蔽站，不是彻底解决

网页有时使用“解决隐藏节点问题”的表达。应改成：

```text
RTS/CTS可以降低或缓解隐蔽站导致的冲突
```

无线冲突无法被完全消除，RTS/CTS 本身也可能冲突，而且它是可选机制。

### 6. p-坚持 CSMA 不要直接等同于 Wi-Fi

网页表格称 p-坚持 CSMA 常用于 Wi-Fi 等网络，这容易造成协议混用。

- p-坚持 CSMA 是适用于时隙信道的基础理论模型。
- 802.11 DCF 使用 CSMA/CA、竞争窗口和随机退避。
- 两者都有概率分散竞争的思想，但不能在统考判断题中直接画等号。

### 7. “纯 CSMA 不重传”不宜作为绝对结论

基本 CSMA 主要规定发送前怎样监听以及信道忙时怎样处理，并未像 CSMA/CD 那样规定边发边检测。是否依赖 ACK 或上层机制发现失败，应看具体协议系统。

考试应记：

```text
CSMA：发送前监听，但仍可能因传播时延发生冲突
CSMA/CD：发送中检测冲突，停止并退避重传
CSMA/CA：通过退避、ACK、可选RTS/CTS尽量避免冲突
```

不要从“基本 CSMA”额外推出过多工程实现结论。

### 8. VLAN 数量要区分编码空间与可用编号

网页说 12 bit VID 支持 4096 个 VLAN，这是在描述编码空间：

$$
2^{12}=4096
$$

更严谨地说：

```text
VID编码值：0~4095，共4096种
通常可用VLAN ID：1~4094
0和4095保留
具体交换机实际支持数量还受设备能力限制
```

统考若只问 12 bit 可表示多少种状态，答 4096；若问通常可配置的 VLAN ID，答 1-4094。

### 9. FDDI 与 IEEE 802.8 的标注不要重点背

网页和王道都把 FDDI 标成 `IEEE 802.8`。这在一些中文教材中很常见，但技术标准归属并不严谨：FDDI 主要由 ANSI X3T9.5 制定并形成 ISO 9314 系列，IEEE 802.8 是光纤技术咨询组，而不是通常意义上的 FDDI 标准编号。

统考更值得记的是：

```text
FDDI：逻辑环形、物理双环、使用光纤
```

标准编号不是本节重点，避免把 `FDDI=IEEE 802.8` 当作必须强化的核心结论。

## 三种标记：以后怎样使用网页内容

### 可以直接记

- 共享介质的基本模型。
- ALOHA、CSMA、CSMA/CD、CSMA/CA 的演化关系。
- 传播时延与发送时延的区别。
- CSMA/CD 最短帧长的因果解释。
- CSMA/CA 的 IFS、NAV 和 RTS/CTS 主流程。
- Ethernet V2 的主要字段和长度。
- 802.11 地址1、2、3的基础口令。
- 一个 VLAN 是一个广播域，跨 VLAN 需要网络层转发。

### 只作理解，不单独当考试结论

- 现实网络已经很少使用共享介质。
- 各协议在工程中的常见程度。
- 将 p-坚持 CSMA 与现代无线协议作类比。
- “Base”所代表的物理信号处理细节。
- 用生活场景比喻 VLAN 或共享信道。

### 必须按王道或修正口径记

- MAC 方法有三类，不能漏掉轮询访问。
- VLAN 标准是 IEEE 802.1Q。
- 1518B 是标准最大 MAC 帧长，常规 MTU 是 1500B。
- 地址4主要与无线分布系统转发有关，不是 Ad Hoc 专用。
- RTS/CTS 只能降低冲突概率。
- 常用 VLAN ID 为 1-4094。

## 推荐学习顺序

### 第一轮：建立直觉

按网页 `mac` 页顺序阅读：

```text
共享介质 -> ALOHA -> CSMA -> CSMA/CD -> CSMA/CA
```

目标是能回答“为什么要从前一个协议改进到后一个协议”。

### 第二轮：按考纲重新归档

```text
王道3.5：多路复用、ALOHA、CSMA、令牌
王道3.6：以太网、CSMA/CD、WLAN、CSMA/CA、VLAN
```

不要因为网页连着讲，就把 FDM、ALOHA 全部塞进 3.6 笔记。

### 第三轮：用真题固定口径

优先完成：

1. CSMA/CD 最短帧长、距离、设备时延。
2. 二进制指数退避。

4. 802.11 三地址。
5. Ethernet V2 与 802.1Q 帧长。
6. VLAN 广播域和跨 VLAN 通信。

## 给你的具体反馈

你先通过这两个网页学习并没有走弯路。网页的组织更适合第一次理解，尤其是共享介质、协议演化和 CSMA/CA 时序；你现在看王道觉得章节错位，实际上说明你已经形成了“按问题理解”的结构，而王道使用的是“按考纲归类”的结构。

当前最需要做的不是推翻原来的理解，而是完成一次重新归档：

```text
把网页MAC页前半部分归入王道3.5
把CSMA/CD归入3.6.2
把CSMA/CA归入3.6.3
把LAN页的HDLC、PPP留到3.7
```

同时修正 `802.3c`、MTU、地址4、RTS/CTS、VLAN ID 这几处表述。完成这一步后，两套资料会从“互相打架”变成“网页帮你理解，王道帮你拿分”。
