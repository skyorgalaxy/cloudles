## 先抓住应用选择的本质

选择栈还是队列，不是看题目出现了什么名词，而是看“下一步应该处理谁”：

| 下一步应处理的对象 | 结构 | 原因 |
| --- | --- | --- |
| 最近产生、尚未处理的对象 | 栈 | LIFO，后进先出 |
| 最早产生、尚未处理的对象 | 队列 | FIFO，先进先出 |

典型映射：

```text
最近的左括号先匹配         -> 栈
最近调用的函数先返回       -> 栈
后缀式中最近两个操作数运算 -> 栈
树中先发现的结点先扩展     -> 队列
先到达的打印任务先处理     -> 队列
```

> [!tip] 选择结构的提问方式
> 不要问“这题像不像栈题”，要问“等待处理的对象中，应该取最新的还是最早的”。

## 3.3.1 括号匹配

### 栈里保存的到底是什么

栈中保存的是“已经出现，但尚未匹配的左括号”。

扫描表达式时：

1. 遇到左括号 `(`、`[`、`{`：入栈。
2. 遇到右括号：检查栈顶是不是对应的左括号。
3. 匹配成功：栈顶出栈。
4. 扫描结束：只有栈空才说明全部匹配。

之所以用栈，是因为最近出现的左括号必须最先被右括号闭合。

```text
[ ( [ ] ) ]
1 2 3 4 5 6

扫描到第4项 ] 时，必须先匹配第3项 [，不能越过它匹配第1项 [。
```

### 三种非法情况

| 情况 | 示例 | 原因 |
| --- | --- | --- |
| 右括号出现时栈空 | `())` | 没有可匹配的左括号 |
| 右括号与栈顶类型不同 | `([)]` | 嵌套次序错误 |
| 扫描结束后栈非空 | `(()` | 仍有左括号未闭合 |

只检查左右括号数量相等不够。`([)]` 数量相等，但次序非法。

### 稳健代码模板

```c
bool BracketsCheck(const char *str) {
    Stack S;
    InitStack(S);

    for (int i = 0; str[i] != '\0'; ++i) {
        char c = str[i];

        if (c == '(' || c == '[' || c == '{') {
            Push(S, c);
        } else if (c == ')' || c == ']' || c == '}') {
            char top;
            if (!Pop(S, top)) return false;

            if ((c == ')' && top != '(') ||
                (c == ']' && top != '[') ||
                (c == '}' && top != '{')) {
                return false;
            }
        }
    }

    return StackEmpty(S);
}
```

> [!warning] 高频代码错误
> 遇到右括号时必须先判断栈是否为空。直接 `Pop` 后再比较，可能发生空栈出栈。

### 栈容量与最大嵌套深度

任意时刻栈中元素数等于当前尚未闭合的左括号数。因此：

```text
括号匹配所需最小栈容量 = 最大括号嵌套深度
```

例如：

```text
([{}])  最大深度为3
([])[]  最大深度为2，不是左括号总数3
```

2025统考真题正是考这个结论：容量为3的栈不能处理最大嵌套深度为4的表达式。

### 易错点

- 最大深度不是左括号总数，而是某一时刻未匹配左括号的最大数量。
- 右括号本身不入栈；它负责检查并弹出左括号。
- 扫描中途栈空不一定错误；只有当前字符是右括号且栈空才错误。
- 扫描结束后必须再检查栈空，不能只看过程中是否发生冲突。

## 3.3.2 表达式求值

### 三种表达式

设运算为 `A+B`：

| 表达式 | 形式 | 运算符位置 | 对应表达式树遍历 |
| --- | --- | --- | --- |
| 前缀 | `+AB` | 操作数之前 | 先序遍历 |
| 中缀 | `A+B` | 两个操作数之间 | 中序遍历，需要括号 |
| 后缀 | `AB+` | 操作数之后 | 后序遍历 |

中缀表达式符合人的习惯，但需要优先级、结合性和括号决定运算顺序。后缀表达式已经把运算顺序编码在排列中，因此不需要括号。

原书示例：

```text
中缀：A+B*(C-D)-E/F
后缀：ABCD-*+EF/-
```

### 手算中缀转后缀

1. 按运算顺序逐层加括号。
2. 将每个运算符移到对应右括号之后。
3. 删除全部括号。

```text
A+B*(C-D)

加括号：  (A+(B*(C-D)))
后移：    (A(B(CD)-)*)+
删除括号：ABCD-*+
```

### 计算机转换法：运算符栈

维护两部分：

- 输出序列：已经确定位置的操作数和运算符。
- 运算符栈：暂时不能确定输出时机的运算符和左括号。

从左向右扫描中缀表达式：

| 扫描项 | 动作 |
| --- | --- |
| 操作数 | 直接输出 |
| `(` | 直接入栈 |
| `)` | 弹出并输出直到遇到 `(`，再丢弃这对括号 |
| 运算符 | 按优先级和结合性决定弹栈，再将当前运算符入栈 |
| 扫描结束 | 将栈中剩余运算符依次输出 |

对于统考常见的左结合运算符 `+ - * /`：

```text
当前运算符优先级 <= 栈顶运算符优先级：弹出栈顶并输出
当前运算符优先级 >  栈顶运算符优先级：当前运算符入栈
```

遇到 `(` 时停止比较。

### 为什么相同优先级也要弹栈

`+ - * /` 都是左结合。例如：

```text
A-B+C = (A-B)+C
```

扫描到 `+` 时，栈顶 `-` 必须先输出，才能保持从左到右运算。

> [!note] 补充：右结合运算符
> 若题目加入乘方 `^`，通常按右结合处理。扫描到另一个 `^` 时不能因“优先级相等”立即弹出，否则会把 `a^b^c` 错算成 `(a^b)^c`。统考基础题一般只用 `+ - * /`，仍要留意题设。

### 2014真题：扫描到某字符时栈里有什么

表达式：

```text
a/b+(c*d-e*f)/g
```

扫描到 `f` 时，运算符栈从栈底到栈顶为：

```text
+  (  -  *
```

原因：

1. 最外层 `+` 尚未到输出时机。
2. 当前仍在括号内部，所以 `(` 仍在栈中。
3. `c*d` 的 `*` 已在扫描到 `-` 时弹出。
4. 当前的 `-` 留在栈中，`e*f` 的 `*` 在其上方。

做这种题时，操作数直接输出，可以只模拟括号和运算符。

### 后缀表达式求值

从左向右扫描后缀表达式：

1. 遇到操作数：入栈。
2. 遇到二元运算符：连续弹出两个操作数。
3. 第一次弹出的是右操作数 `y`，第二次弹出的是左操作数 `x`。
4. 计算 `x op y`，结果重新入栈。
5. 扫描结束后，栈中应恰好剩一个结果。

```c
y = Pop(S);          // 先弹出右操作数
x = Pop(S);          // 后弹出左操作数
Push(S, x op y);
```

> [!danger] 高频失分点
> 对减法和除法，不能写成 `y-x` 或 `y/x`。第一次弹出的元素位于表达式右侧。

示例：后缀式 `82-`：

```text
8入栈，2入栈
先弹出2作为右操作数
再弹出8作为左操作数
结果为8-2=6
```

### 用栈高度判断后缀式

若只含二元运算符，可用一个计数器模拟栈中操作数数量：

```text
遇到操作数：高度 +1
遇到运算符：先要求高度 >=2，再令高度 -1
```

因为两个操作数出栈、一个结果入栈，净变化是 `-1`。

用途：

- 判断后缀表达式是否合法。
- 计算求值栈的最大深度。
- 快速判断给定容量是否会溢出。

合法后缀式必须满足：

```text
扫描任何运算符前，栈高度至少为2
扫描结束后，栈高度恰好为1
```

### 运算符栈深度与操作数栈深度不要混

| 题目描述 | 应模拟的栈 |
| --- | --- |
| 中缀转后缀时暂存运算符 | 运算符栈 |
| 后缀表达式求值 | 操作数栈 |
| 括号最大嵌套深度 | 括号栈 |

2012统考题问的是中缀转后缀过程中“同时保存的运算符最大个数”，括号也在运算符栈中，不能漏算。

### 表达式题易错点

- 左括号入栈，但不会出现在后缀表达式中。
- 右括号不入栈，只负责弹出到左括号。
- 扫描结束后别忘了清空运算符栈。
- 操作数的相对次序在中缀转后缀时不会改变。
- 栈中书写顺序要先确认题目要求“栈底到栈顶”还是“栈顶到栈底”。
- 多位数和变量名应作为完整记号处理，不能逐字符拆开。

## 3.3.3 递归与调用栈

### 递归成立的两个条件

1. 递归体：把原问题转化为规模更小的同类问题。
2. 递归出口：在有限步内停止递归。

缺少出口会无限递归；规模没有向出口收敛，也会无限递归。

### 每一层调用保存什么

函数每调用一次，系统通常建立一个活动记录并压入调用栈，保存：

- 返回地址
- 实际参数或参数信息
- 局部变量
- 必要的寄存器和现场信息

最近调用的函数最先返回，所以使用栈。

```text
main 调用 S(1)，S(1) 调用 S(0)

栈顶  S(0)   <- 最先返回
      S(1)
栈底  main
```

2015统考题从栈底到栈顶的顺序是：

```text
main -> S(1) -> S(0)
```

### 调用次数和递归深度是两回事

| 概念 | 含义 |
| --- | --- |
| 调用次数 | 递归调用树的结点总数 |
| 最大递归深度 | 从根到最深结点的调用链长度 |
| 同时占用的栈帧数 | 通常与最大递归深度对应 |

分支递归可能调用很多次，但同时存在的栈帧只对应当前正在深入的一条路径。

### 画递归调用树

对：

```c
F(n) = F(n-2) + F(n-4) + 1
```

先画根 `F(n)`，再按代码中的调用顺序画子结点。常用结论：

- 总调用次数 = 树中结点总数。
- 最大递归深度 = 最长根到叶路径的结点数。
- 函数开始执行的先后次序 = 调用树的先序次序。

### 为什么递归常比迭代慢

- 每层调用都要建立、保存和恢复栈帧。
- 分支递归可能重复求解相同子问题。
- 递归深度过大可能导致栈溢出。

但“递归一定慢”也不准确；性能取决于算法、编译器优化和问题规模。考试中的稳妥表述是：通常递归的额外调用开销更大，朴素分支递归还可能包含大量重复计算。

### 消除递归一定要栈吗

不一定。

- 一般递归可用显式栈模拟。
- 尾递归、单向递归有时可直接改写为循环。
- 若递归需要保存多个未完成分支，显式栈通常最自然。

因此“非递归改写递归程序必须使用栈”是错误说法，也是2017统考题的考点。

### 递归题易错点

- 把总调用次数当成最大栈深度。
- 只算递归调用，不把最初那次函数调用计入总次数。
- 忘记递归出口也会执行一次函数调用。
- 分析 `func(func(5))` 时，必须先完整求内层参数，再调用外层。
- 栈底是最早调用者，栈顶是当前正在执行的最深层函数。

## 3.3.4 层次遍历与广度优先搜索

### 为什么层次遍历使用队列

访问当前结点时，把它的孩子按顺序加入队尾。由于先发现的结点先出队，所以能保证逐层访问。

```text
根结点入队
重复：队首出队并访问 -> 左孩子入队 -> 右孩子入队
直到队空
```

### 二叉树层次遍历模板

```c
void LevelOrder(BiTree root) {
    if (root == NULL) return;

    Queue Q;
    InitQueue(Q);
    EnQueue(Q, root);

    while (!QueueEmpty(Q)) {
        BiTree p;
        DeQueue(Q, p);
        Visit(p);

        if (p->lchild != NULL) EnQueue(Q, p->lchild);
        if (p->rchild != NULL) EnQueue(Q, p->rchild);
    }
}
```

顺序是“出队访问，再让孩子入队”。如果题目规定先右后左入队，同层访问顺序也会随之改变。

### 从层次遍历推广到图的 BFS

树没有回边，一个结点通常只会被父结点发现一次；图可能有环，因此必须记录 `visited`。

```c
visited[start] = true;
EnQueue(Q, start);

while (!QueueEmpty(Q)) {
    v = DeQueue(Q);
    Visit(v);

    for (每个邻接点 w) {
        if (!visited[w]) {
            visited[w] = true;
            EnQueue(Q, w);
        }
    }
}
```

> [!warning] BFS 标记时机
> 通常在“入队时”标记已访问。若等到出队才标记，同一结点可能被多个前驱重复入队。

若图不连通，只从一个起点 BFS 不能访问全部顶点，需要在外层扫描所有未访问顶点并再次启动 BFS。

### BFS 与 DFS 对照

| 对比 | BFS | DFS |
| --- | --- | --- |
| 辅助结构 | 队列 | 栈或递归 |
| 扩展顺序 | 先发现先扩展 | 最近发现先深入 |
| 树上的对应遍历 | 层次遍历 | 先序/中序/后序等深度遍历 |
| 无权图最短边数路径 | 可以求得 | 不保证 |

NIST 的算法与数据结构词典也将层次遍历视为从根开始的广度优先搜索，并把 FIFO 作为 BFS 的关键处理顺序。

### 层次遍历易错点

- 根结点为空时不要入队。
- 结点出队后才访问，还是入队时访问，要按算法约定保持一致。
- 左右孩子入队顺序决定同层输出顺序。
- 图的 BFS 必须防止重复访问；树的层次遍历通常不需要 `visited`。
- “广度优先”使用普通队列；Dijkstra 等按代价选结点的算法通常需要优先队列，不能混为一谈。

## 3.3.5 队列在计算机系统中的应用

### 缓冲区

生产者和消费者速度不匹配时，可以用队列保存尚未处理的数据：

```text
主机高速产生打印数据 -> 缓冲队列 -> 打印机低速处理
```

要求保持原数据顺序，所以应使用 FIFO 队列，而不是栈。

2009统考题中，打印缓冲区的逻辑结构答案是队列。

### 请求与任务调度

- 先来先服务 FCFS：请求按到达时间入队，队首先处理。
- 时间片轮转 RR：任务从队首取得时间片，未完成则重新进入队尾。
- I/O 请求队列：设备按调度策略处理等待请求。
- 消息队列：发送者和接收者解耦，消息按约定顺序处理。

注意：若系统按优先级而不是到达时间选择任务，使用的是优先队列思想，不再是简单 FIFO。

### FIFO 页面替换

将当前驻留页面按进入内存的时间排队：

- 新页面进入时加入队尾。
- 需要替换时淘汰队首的最早页面。

因此 FIFO 页面替换使用队列。它只看进入时间，不看页面最近是否被访问。

### 多轨道列车题

每条轨道相当于一个队列。若最终要求按编号递增驶出，则同一轨道内必须保持递增：

```text
轨道内先进入的列车必须先驶出
所以后进入同一轨道的编号不能更小
```

2016统考题输入：

```text
8,4,2,5,3,9,1,6,7
```

可分为4条递增轨道，例如：

```text
轨道A：8,9
轨道B：4,5,6,7
轨道C：2,3
轨道D：1
```

所以至少需要4条轨道。

> [!note] 补充规律
> 将一个序列划分成尽量少的严格递增子序列，最少子序列数等于原序列的最长严格递减子序列长度。基础做题时可用贪心分轨；理解这个结论后可快速验证“至少需要几条轨道”。

一种手算贪心：处理当前编号 `x` 时，把它接到“队尾小于 `x` 且尽量接近 `x`”的轨道；若不存在这样的轨道，就新开一条。

### 系统应用易错点

- 缓冲区不一定都是队列；只有要求按到达顺序处理时才是 FIFO 队列。
- 时间片轮转中，未完成进程通常回到队尾，不是原地等待。
- 优先级调度使用优先队列思想，不保证先到先服务。
- FIFO 页面替换中的“最早”指最早进入内存，不是最久未访问。

### 2018双栈求值：一定写左右操作数

题目每次从操作数栈弹出 `a`、`b`，执行 `b op a`。初始：

```text
S1栈底 -> 5,8,3,2 <- 栈顶
S2栈底 -> *,-,+  <- 栈顶
```

```text
3+2=5
8-5=3
5*3=15
```

最终栈顶为15。

这题本质仍是：第一次弹出的是右操作数，第二次弹出的是左操作数。

## 一页速记

```text
括号匹配：左括号入栈；右括号匹配栈顶；结束必须栈空
括号栈最大深度 = 最大嵌套深度

中缀转后缀：操作数直接输出；( 入栈；) 弹到 (
左结合运算符：当前优先级 <= 栈顶时，先弹栈
后缀求值：先弹右操作数，再弹左操作数

递归：每层调用一个栈帧；最近调用最先返回
总调用次数看调用树结点数；最大栈深看最长调用链

层次遍历/BFS：先发现先处理，用队列
图的BFS通常在入队时标记visited

缓冲区、FCFS、RR、FIFO页面替换：常见队列应用
多轨道队列：每条轨道内部必须保持递增
```

## 易错点总清单

- [x] 括号数量相等不代表匹配正确
- [x] 最大嵌套深度不等于左括号总数
- [x] 中缀转后缀时括号不出现在结果中
- [ ] 同优先级左结合运算符需要先弹栈
- [x] 后缀求值第一次弹出的是右操作数
- [x] 运算符栈深度和操作数栈深度不是同一个问题
- [x] 递归总调用次数不等于最大递归深度
- [x] 非递归改写不一定必须使用显式栈
- [x] BFS通常在入队时标记访问
- [x] 图不连通时一次BFS不能遍历全部顶点
- [x] FIFO页面替换看进入时间，不看最近访问时间
- [ ] 多轨道题中同一队列必须保持目标输出顺序

## 自测顺序

1. 手算3个括号串，并写出每一步栈内容。
2. 把 `A*(B+C)-D/E` 转成后缀表达式。
3. 用栈求值 `82-3*`，每步标注左右操作数。
4. 画一个分支递归的调用树，分别计算调用次数和最大深度。
5. 手动执行一棵二叉树的层次遍历，记录每次出队和入队。
6. 用贪心法把一个乱序序列分配到尽量少的递增队列。
