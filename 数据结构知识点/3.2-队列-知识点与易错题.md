## 一句话抓住队列

队列是只允许在一端插入、另一端删除的线性表。插入的一端叫队尾，删除的一端叫队首。

- 入队：EnQueue，在队尾插入
- 出队：DeQueue，在队首删除
- 核心规律：FIFO，先进先出

队列与栈的逻辑结构相同，都是线性表；二者的根本区别是插入和删除的位置限制不同。

## 顺序队列：普通数组为什么会假溢出

若用数组存储队列，`front` 指向队首，`rear` 指向下一个入队位置：

```text
入队：data[rear] = x; rear++
出队：x = data[front]; front++
队空：front == rear
```

当元素出队后，数组前部会留下空位置。若 `rear` 继续向右移动，即使前面有空位，也可能因为 `rear` 到达数组末端而无法入队，这叫假溢出。

解决方法：循环队列，或移动元素，但移动元素会增加时间开销。

## 循环队列

### 常见约定A：牺牲一个空位

数组下标为 `0...MaxSize-1`，`front` 指向队首元素，`rear` 指向队尾元素的下一个位置。

```text
初始：front = rear = 0
入队：data[rear] = x; rear = (rear + 1) % MaxSize
出队：x = data[front]; front = (front + 1) % MaxSize
队空：front == rear
队满：(rear + 1) % MaxSize == front
队列长度：(rear - front + MaxSize) % MaxSize
```

该方案最多存放 `MaxSize-1` 个元素，因为必须保留一个空位置区分“空”和“满”。

### 常见约定B：增加 size 或 tag

如果希望数组的 `MaxSize` 个位置都能存放元素，需要额外记录：

- `size`：元素个数为0表示空，为 `MaxSize` 表示满
- 或 `tag`：在 `front==rear` 时，用 tag 区分刚刚入队导致的满和刚刚出队导致的空

易错点：队满条件不能脱离题目约定。看到 `front`、`rear` 后，先判断它们各自指向什么。

## 循环队列画图法

遇到取模题，不要只在脑中计算。画一个环并标记 `front`、`rear`：

```text
0 -> 1 -> 2 -> ... -> MaxSize-1
^                         |
|_________________________|
```

每次移动都执行：

```text
next = (current + 1) % MaxSize
```

尤其注意：`rear` 指向“下一个空位”时，`rear` 本身不一定存有队尾元素。

## 链式队列

链式队列通常用带队首指针和队尾指针的单链表表示：

```text
front -> 队首结点 -> ... -> 队尾结点 <- rear
```

若不带头结点：

- 空队列：`front == NULL` 且 `rear == NULL`
- 入队到空队列：`front = rear = s`
- 非空入队：`rear->next = s; rear = s`
- 出队最后一个结点后：必须同时令 `front = rear = NULL`

若带头结点：

- `front` 常指向头结点
- `rear` 指向最后一个实际数据结点
- 空队列常用 `front == rear` 判断

不要把带头结点和不带头结点的空、入、出代码混用。

## 双端队列

双端队列允许在两端进行插入和删除，但题目可能进一步限制一端的输入或输出。

| 类型 | 插入限制 | 删除限制 |
| --- | --- | --- |
| 普通双端队列 | 两端均可 | 两端均可 |
| 输入受限双端队列 | 只能从一端插入 | 两端均可删除 |
| 输出受限双端队列 | 两端均可插入 | 只能从一端删除 |

易错点：先读清“受限”的是输入还是输出。只允许一端插入，不等于只允许一端删除。

## 队列题型和易错点

### 题型1：栈和队列比较

- 共同点：都是操作受限的线性表。
- 栈：一端进出，LIFO。
- 队列：一端进、一端出，FIFO。
- 不要说二者逻辑结构不同；不同的是基本操作的限定。

### 题型2：循环队列判空判满

固定四步：

1. 写数组下标范围。
2. 写 `front` 的含义。
3. 写 `rear` 的含义。
4. 再推导空、满、长度和移动公式。

在“牺牲一个空位”的模型中：

```text
空：front == rear
满：(rear + 1) % MaxSize == front
长度：(rear - front + MaxSize) % MaxSize
```

### 题型3：循环队列操作模拟

建议每一步写成表格：

| 操作 | front | rear | 队列逻辑内容 |
| --- | ---: | ---: | --- |
| 初始 | 0 | 0 | 空 |
| 入队 a | 0 | 1 | a |
| 入队 b | 0 | 2 | a,b |
| 出队 | 1 | 2 | b |

只看数组中的物理位置容易误判，题目问的是逻辑顺序。

### 题型4：链式队列代码

最容易漏掉的分支是“出队后队列变空”。如果删除前 `front==rear`，删除后必须同时修改队首和队尾；否则 `rear` 会悬空，下一次入队可能接到错误位置。

### 题型5：双端队列输出序列

先判断每个元素能从哪一端进入、哪一端出去，再做局部模拟。不要直接套栈的后进先出，也不要直接套队列的先进先出。

## 栈和队列常见应用对照

| 应用 | 结构 | 原因 |
| --- | --- | --- |
| 括号匹配 | 栈 | 最近出现的左括号最先匹配 |
| 表达式求值 | 栈 | 运算符和操作数需要后进先处理 |
| 函数调用/递归 | 栈 | 最近调用的函数最先返回 |
| 层次遍历 | 队列 | 先访问的层先扩展 |
| 缓冲区 | 队列 | 保持数据到达顺序 |
| 生产者-消费者 | 队列 | 先到的数据先被处理 |

## 一页速记

```text
队列：队尾进，队首出，FIFO
普通顺序队列会假溢出
循环队列：移动都取模
牺牲一个空位：空 front==rear，满 next(rear)==front
长度：(rear-front+MaxSize)%MaxSize
链队列：空队列、最后一个结点出队是重点
双端队列：看清限制的是输入端还是输出端
```

## 补充理解：先别背公式，先理解“队伍”

如果把队列想成排队买票：

```text
进队方向                         出队方向
新来的人 -> [队尾] ... [队首] -> 离开
             EnQueue       DeQueue
```

队列只有两个动作：

- 新元素只能从队尾进入，所以入队改变 `rear`。
- 老元素只能从队首离开，所以出队改变 `front`。
- 中间元素不能跳出来，也不能从中间插入。

这就是 FIFO：先进去的人先出来。只要题目没有改变这个规则，就不要把队列当成栈来想。

## 普通顺序队列：为什么会有假溢出

先用一个长度为 5 的数组模拟：

```text
下标：  0   1   2   3   4
       [ ] [ ] [ ] [ ] [ ]
```

依次入队 `a,b,c,d,e`：

```text
       [a] [b] [c] [d] [e]
front=0                 rear=5
```

再出队 `a,b,c`：

```text
       [ ] [ ] [ ] [d] [e]
                   front=3  rear=5
```

此时数组前面明明有 3 个空位置，但 `rear` 已经到达数组末端。如果仍然规定“只能把新元素放到 `data[rear]`”，就不能继续入队。这叫假溢出：

> 物理数组还有空位，但线性移动的队尾指针已经走到尽头。

解决假溢出有两个方向：

1. 把剩余元素整体向前移动，但移动可能需要 `O(n)` 时间。
2. 让数组首尾相接，形成循环队列，通常这是考研题的重点。

## 循环队列：它到底“循环”了什么

循环队列不是把数据真的搬来搬去，而是让下标到达末尾后回到 0：

```text
next(i) = (i + 1) % MaxSize
```

例如 `MaxSize=5`：

```text
next(0)=1, next(1)=2, next(2)=3, next(3)=4, next(4)=0
```

所以循环队列的数组可以画成：

```text
       0 -> 1 -> 2 -> 3 -> 4
       ^                   |
       |___________________|
```

`front` 和 `rear` 不再只会向右增加，它们每次移动都要取模。

## 最常见的循环队列约定

王道题目最常见的约定是：

- `front` 指向队首元素
- `rear` 指向队尾元素的下一个位置
- 牺牲一个数组单元，用来区分“空”和“满”

### 为什么 `front == rear` 表示空

初始化时没有元素：

```text
front = 0
rear  = 0
```

入队 `a`：把 `a` 放到 `data[rear]`，然后 `rear` 向后移动：

```text
入队前：front=0, rear=0
放入a： data[0]=a
移动后：front=0, rear=1
```

出队 `a`：读取 `data[front]`，然后 `front` 向后移动：

```text
出队前：front=0, rear=1
读取a： data[0]
移动后：front=1, rear=1
```

出队后又回到 `front == rear`，所以它表示空队列。

### 为什么满不是 `front == rear`

如果把数组全部放满，`rear` 绕一圈后也会追上 `front`，这会和空队列的状态完全一样。为了区分二者，规定永远留一个空位置：

```text
队空：front == rear
队满：(rear + 1) % MaxSize == front
```

因此，数组长度为 `MaxSize` 的循环队列，实际最多存 `MaxSize-1` 个元素。

## 用一个具体例子理解“牺牲一个空位”

设 `MaxSize=5`，可用下标 `0,1,2,3,4`，最多存 4 个元素。

```text
初始：front=0, rear=0
入队a：front=0, rear=1
入队b：front=0, rear=2
入队c：front=0, rear=3
入队d：front=0, rear=4
```

此时数组中有 4 个元素，`rear=4`。如果再入队：

```text
(rear + 1) % 5 = 0 = front
```

说明再入队会追上 `front`，因此队满。

出队 `a` 后：

```text
front=1, rear=4
```

此时又空出下标 0。再入队 `e`：

因为本约定中 `rear=4` 指向下一个空位，所以把 `e` 放入 `data[4]`，之后：

```text
rear = (4 + 1) % 5 = 0
```

如果继续入队，才会使用 `data[0]`。这就是“逻辑上排在后面，物理位置可能绕回数组开头”。

## 循环队列的四个公式从哪里来

不要把公式当成孤立结论。它们都来自“指针沿环向前走”。

### 入队

```c
Q.data[Q.rear] = x;
Q.rear = (Q.rear + 1) % MaxSize;
```

含义：先占用 `rear` 当前指向的空位，再让 `rear` 指向新的空位。

### 出队

```c
x = Q.data[Q.front];
Q.front = (Q.front + 1) % MaxSize;
```

含义：先取走 `front` 指向的队首元素，再让 `front` 指向新的队首。

### 队列长度

```text
(rear - front + MaxSize) % MaxSize
```

分两种情况理解：

- `rear >= front`：元素数是 `rear-front`。
- `rear < front`：队尾已经绕回数组开头，元素数是 `MaxSize-front+rear`。

统一写法就是加上 `MaxSize` 后取模。

### 队满

移动一步后的 `rear` 追上 `front`：

```text
(rear + 1) % MaxSize == front
```

## 一定要分清的三种指针语义

| 题目说法 | 指针含义 | 入队时先做什么 |
| --- | --- | --- |
| `rear` 指向队尾元素 | 指向已经存放的数据 | 先移动到下一个位置，再存入，或按题目代码判断 |
| `rear` 指向队尾元素的下一个位置 | 指向空位 | 先存入，再移动 |
| `front` 指向队首元素的前一个位置 | 指向队首前的空位 | 出队时先移动，再取数据 |

考试中不能因为见过某一套公式，就默认所有题都采用同一语义。看到“指向队尾元素”与“指向队尾元素的下一个位置”，代码会完全不同。

## 循环队列题的机械解法

遇到具体操作序列，按下面的表格做，不要凭感觉：

| 步骤 | 操作 | front | rear | 逻辑队列 |
| ---: | --- | ---: | ---: | --- |
| 0 | 初始化 | 0 | 0 | 空 |
| 1 | 入队 a | 0 | 1 | a |
| 2 | 入队 b | 0 | 2 | a,b |
| 3 | 出队 | 1 | 2 | b |
| 4 | 入队 c | 1 | 3 | b,c |

每次都只问三个问题：

1. 数据放在哪个下标？
2. 哪个指针要移动？
3. 移动后是否需要取模？

## 链式队列：只抓住两个特殊情况

链式队列不需要预先固定数组容量，结点通常动态申请。

```text
front -> [a] -> [b] -> [c] <- rear
```

### 普通入队

新结点永远接到 `rear` 后面：

```c
s->next = NULL;
Q.rear->next = s;
Q.rear = s;
```

### 空队列入队

如果原来没有结点，`front` 和 `rear` 都要指向新结点：

```c
Q.front = Q.rear = s;
```

### 出队最后一个结点

如果出队前只有一个结点，删掉它之后必须让两个指针都为空：

```c
if (Q.front == Q.rear) {
    Q.front = Q.rear = NULL;
}
```

这是链式队列最常考的边界。只改 `front` 不改 `rear`，会留下一个失效的队尾指针。

## 把栈和队列放在一起比较

| 问题 | 栈 | 队列 |
| --- | --- | --- |
| 新元素从哪里进 | 栈顶 | 队尾 |
| 哪个元素先出 | 最后进入的 | 最先进入的 |
| 删除位置 | 栈顶 | 队首 |
| 典型应用 | 递归、括号、表达式、回溯 | 缓冲区、层次遍历、任务排队 |
| 记忆句 | 一端进出 | 一端进、一端出 |

## 你做题时最容易掉进去的坑

### 坑1：把“数组有空位”当成“队列还能入队”

普通顺序队列中，前面的空位不代表 `rear` 能回头使用；这正是假溢出。只有循环队列允许逻辑上的回绕。

### 坑2：把 `rear` 当成队尾元素

很多循环队列题里，`rear` 指向的是下一个空位，所以真正的队尾元素在：

```text
(rear - 1 + MaxSize) % MaxSize
```

不要直接读 `data[rear]` 当作队尾元素。

### 坑3：看到 `front == rear` 就直接选“队空”

它通常表示队空，但在使用 `size` 或 `tag` 的实现中，`front == rear` 还可能表示队满。必须看题目有没有额外变量。

### 坑4：忘记取模

循环队列中只要是指针移动，几乎都要检查 `% MaxSize`。漏掉取模，做几步后就会越出数组范围。

### 坑5：把物理下标顺序当成逻辑顺序

循环队列可能出现：

```text
data[3] = b, data[4] = c, data[0] = d
```

逻辑顺序仍然是 `b,c,d`，因为顺序由 `front` 沿环移动决定，不由数组下标从小到大决定。

## 建议的学习顺序

1. 先只用纸笔模拟普通队列的入队、出队。
2. 理解普通队列的假溢出。
3. 记住循环队列的 `next(i)`，自己推导空、满、长度。
4. 做带 `front/rear` 的操作序列题。
5. 最后学习链式队列和双端队列。

如果循环队列仍然混乱，先暂时不背“满”的公式，只画出 `front` 和 `rear` 的位置，问自己：

> 队首从哪里出？队尾下一个元素应该放在哪里？两个指针谁在追谁？
