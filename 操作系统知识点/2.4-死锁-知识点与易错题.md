# 2.4 死锁 - 知识点与易错题

> 原书：第149-175页；PDF第160-186页

## 1. 死锁概念

死锁是多个进程因竞争不可剥夺资源而形成循环等待，若无外力将永久阻塞。

相关概念：

- 饥饿：进程长期得不到资源或 CPU，其他进程仍在推进，不一定有环。
- 死循环：单个进程逻辑错误反复执行，通常仍处于运行/就绪。
- 死锁：一组进程互相等待，组内都不能推进。

## 2. 四个必要条件

死锁发生必须同时满足：

1. 互斥：资源一次只能被一个进程使用。
2. 不剥夺：资源只能由持有者主动释放。
3. 请求并保持：持有资源的同时请求新资源。
4. 循环等待：存在进程-资源闭合等待链。

四者都是必要非充分条件；同时存在时才可能死锁，某些多实例资源图即使有环也未必死锁。

## 3. 资源分配图

- 进程结点 -> 资源结点：请求边。
- 资源实例 -> 进程结点：分配边。

若每类资源只有一个实例，图中存在环可判死锁；若有多个实例，环只是可能死锁，需进一步检测。

## 4. 死锁处理策略

| 策略 | 思想 | 特点 |
| --- | --- | --- |
| 预防 | 破坏必要条件 | 简单保守，资源利用率低 |
| 避免 | 分配前判断安全性 | 需预知最大需求，银行家算法 |
| 检测与解除 | 允许发生，定期检测 | 利用率高，恢复有代价 |
| 忽略 | 假设概率低，由用户处理 | 通用系统常见务实策略 |

## 5. 死锁预防

### 破坏互斥

把独占资源改造成可共享，如 SPOOLing 把打印输出先写入磁盘队列。并非所有资源都能共享。

### 破坏不剥夺

请求新资源失败时释放已占资源，或由系统剥夺资源。适合 CPU、内存等状态易保存资源，不适合打印机等。

### 破坏请求并保持

进程开始前一次申请全部资源，或只有不持有资源时才申请。资源利用率低，可能饥饿。

### 破坏循环等待

给资源类型统一编号，进程必须按递增顺序申请。注意它限制的是资源**类型顺序**，同类多个实例可一次申请。

## 6. 安全状态与死锁避免

安全状态：系统存在某个进程执行顺序，使每个进程都能依靠当前可用资源加上前面进程释放的资源完成，该顺序称安全序列。

```text
安全状态 -> 一定无死锁
不安全状态 -> 可能死锁，但不等于已死锁
死锁状态 -> 一定不安全
```

## 7. 银行家算法

数据结构：

```text
Available：各类当前可用资源
Max[i]：进程i最大需求
Allocation[i]：已分配资源
Need[i] = Max[i] - Allocation[i]
Request[i]：本次请求
```

请求检查：

```text
1. Request_i <= Need_i，否则超出声明
2. Request_i <= Available，否则进程等待
3. 试分配：
   Available -= Request_i
   Allocation_i += Request_i
   Need_i -= Request_i
4. 运行安全性算法
5. 安全则正式分配；不安全则撤销试分配
```

### 安全性算法

```text
Work = Available
Finish[i] = false

寻找 Finish[i]=false 且 Need[i] <= Work 的进程
若找到：Work += Allocation[i]，Finish[i]=true，记录序列，继续
若最终全部 Finish=true：安全
否则：不安全
```

比较向量必须逐分量满足，不能比较资源总数之和。

## 8. 死锁检测

与安全性算法类似，但检测当前还需资源 `Request/Need_current`：

```text
Work = Available
能满足的进程视为可完成，并回收其 Allocation
反复查找，最后仍不能标记完成的进程属于死锁集合
```

若某进程当前 Allocation 全 0，可按具体算法初始化为可结束/非死锁，题目通常会给出口径。

## 9. 死锁解除

- 资源剥夺：选择牺牲进程，回滚后重试；应避免同一进程反复被牺牲而饥饿。
- 撤销进程：一次或逐个终止死锁进程，释放资源。
- 进程回退：恢复到安全检查点，需保存状态。

牺牲者选择可考虑优先级、已运行时间、剩余时间、占用资源、还需资源、交互/批处理性质和回滚成本。

## 10. 与同步题结合

PV 顺序不当会形成死锁。检查方法：

```text
列出每个进程已持有的信号量
 -> 标出继续执行前等待的信号量
 -> 若形成闭环，检查是否满足四条件
```

统一资源申请顺序是破坏循环等待的常用方法。

## 易错点

- [ ] 把饥饿、死循环和死锁混为一谈
- [ ] 认为资源分配图有环一定死锁
- [ ] 四个必要条件任一满足就会死锁
- [ ] 不安全状态等同于已经死锁
- [ ] 安全序列必须唯一
- [ ] 银行家算法先正式分配再检查
- [ ] `Need` 与本次 `Request` 混淆
- [ ] 向量比较用总和代替逐项比较
- [ ] 检测算法中进程完成后忘记释放 Allocation
- [ ] 有序申请资源破坏的是请求并保持（实际破坏循环等待）

## 一页背诵版

```text
死锁四条件：互斥、不剥夺、请求并保持、循环等待

预防：破坏至少一个必要条件
避免：保持安全状态，银行家算法
检测：允许发生，查找不能完成的进程集合
解除：剥夺、撤销、回退

Need = Max - Allocation
请求：先查Request<=Need、Request<=Available
试分配后再做安全性检查

安全一定不死锁
不安全不等于已死锁
单实例资源图有环可判死锁；多实例不一定
```
