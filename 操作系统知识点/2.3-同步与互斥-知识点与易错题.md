# 2.3 同步与互斥 - 知识点与易错题

> 原书：第99-148页；PDF第110-159页

## 1. 基本概念

- 临界资源：一次只允许一个进程使用的资源。
- 临界区：访问临界资源的代码段。
- 进入区：检查并申请进入临界区。
- 退出区：释放使用权。
- 剩余区：其他代码。

互斥是对临界资源的排他访问；同步是并发进程因合作产生的执行先后约束。

### 临界区准则

1. 空闲让进：临界区空闲时允许申请者进入。
2. 忙则等待：已有进程在临界区时其他进程不能进入。
3. 有限等待：申请者应在有限时间内进入，避免饥饿。
4. 让权等待：不能进入时尽量释放 CPU，非所有低级算法都满足。

## 2. 软件实现

### 单标志法

严格轮流进入；可保证互斥，但一方不进入时另一方也无法连续进入，违背空闲让进。

### 双标志先检查

先检查对方标志再设置自己标志；检查和设置不是原子操作，可能双方同时进入，违背忙则等待。

### 双标志后检查

先设置自己标志再检查对方；可能双方都等待，产生饥饿/死等，违背空闲让进与有限等待。

### Peterson 算法

```c
flag[i] = true;
turn = j;
while (flag[j] && turn == j) ;
// critical section
flag[i] = false;
```

适用于两个进程，满足互斥、空闲让进和有限等待，但忙等待，不满足让权等待。现代弱内存模型下还需内存屏障，统考按经典顺序一致模型理解。

## 3. 硬件实现

- 中断屏蔽：单核内核短临界区可用；多核上不能阻止其他 CPU，且不应交给用户程序。
- TestAndSet：原子读旧值并置 1。
- Swap/Exchange：原子交换锁变量与寄存器。
- CompareAndSwap：值等于期望值时原子更新。

自旋锁在等待时持续占用 CPU，适合多核、持锁时间很短且不能睡眠的场景；单核或长临界区效率低。

## 4. 信号量

### 整型信号量

对整数执行原子 wait/signal，但 wait 中忙等，不满足让权等待。

### 记录型信号量

```text
wait(S):
    S.value--
    if S.value < 0:
        block当前进程并加入S等待队列

signal(S):
    S.value++
    if S.value <= 0:
        wakeup等待队列中的一个进程
```

含义：

- `S.value >= 0`：当前可用资源数。
- `S.value < 0`：其绝对值通常表示等待进程数。

PV 操作必须是原子操作。`wait/P/down` 申请，`signal/V/up` 释放或通知。

### 互斥与同步模板

互斥：

```c
semaphore mutex = 1;
P(mutex);
// critical section
V(mutex);
```

前驱关系 `S1 -> S2`：

```c
semaphore sync = 0;

P1: S1; V(sync);
P2: P(sync); S2;
```

互斥信号量初值通常 1；同步信号量初值取决于初始可发生事件数，常为 0；资源信号量初值为资源数量。

## 5. 管程

管程把共享数据、对数据的操作和初始化封装在一起：

- 任一时刻通常只允许一个进程在管程内活动，天然提供互斥；
- 条件变量用于等待某条件，不是资源计数器；
- `x.wait()` 使调用者阻塞并释放管程；`x.signal()` 唤醒等待者，具体立即交接或继续执行依管程语义。

Java `synchronized` 等可体现管程思想。

## 6. 生产者-消费者

容量为 n 的有界缓冲区：

```c
semaphore mutex = 1;
semaphore empty = n;
semaphore full = 0;

producer:
    produce(item);
    P(empty);
    P(mutex);
    put(item);
    V(mutex);
    V(full);

consumer:
    P(full);
    P(mutex);
    get(item);
    V(mutex);
    V(empty);
    consume(item);
```

先申请资源信号量，再申请互斥量。若先锁 mutex 再等待 empty/full，可能持锁阻塞，另一方无法进入，造成死锁。

## 7. 读者-写者

要求：多个读者可并发；写者与任何读/写互斥。

读者优先基本结构：

```c
semaphore rw = 1, mutex = 1;
int count = 0;

reader:
    P(mutex);
    if (++count == 1) P(rw);
    V(mutex);
    read();
    P(mutex);
    if (--count == 0) V(rw);
    V(mutex);

writer:
    P(rw); write(); V(rw);
```

`mutex` 保护计数变量，`rw` 保护共享对象。持续到达的读者可能使写者饥饿；可增设闸门信号量实现写优先或公平。

## 8. 哲学家进餐

若每人先拿左筷子再拿右筷子，可能循环等待。常见解决：

- 最多允许 4 人同时尝试进餐；
- 奇偶哲学家采用相反取筷顺序；
- 一次原子申请两根筷子；
- 由服务员统一分配。

核心是破坏死锁条件，而非仅保证单根筷子互斥。

## 9. 吸烟者问题

三个吸烟者各自拥有一种材料，供应者每次放另外两种。为三种组合设置同步信号量，供应者通知对应吸烟者；吸烟者完成后通知供应者继续。用于训练“事件发生一次，V；等待事件，P”的同步建模。

## 10. PV 解题步骤

```text
1. 找进程和重复结构
2. 找共享资源，设置mutex=1
3. 找前驱事件，为每类事件设同步信号量
4. 根据信号初始是否已发生确定初值
5. P放在必须等待的动作之前，V放在事件完成之后
6. 检查P顺序是否形成占有并等待
7. 检查资源计数、互斥范围和循环末尾是否配对
```

## 易错点

- [ ] 互斥和同步概念混用
- [ ] 临界资源等同于临界区代码
- [ ] Peterson 算法满足让权等待
- [ ] 自旋锁等待时会主动让出 CPU
- [ ] 信号量负值仍解释为可用资源数
- [ ] 把条件变量当计数信号量
- [ ] 生产者先 P(mutex) 再 P(empty)
- [ ] 读者计数变量未受互斥保护
- [ ] PV 不成对就必然错误（同步信号量可跨进程成对）
- [ ] 只保证筷子互斥就认为哲学家不会死锁

## 一页背诵版

```text
同步：合作产生先后关系
互斥：临界资源排他访问
准则：空闲让进、忙则等待、有限等待、让权等待

mutex初值1；同步量常为0；资源量初值=资源数
P：先减，负则阻塞
V：先加，<=0则唤醒

生产者：P(empty)->P(mutex)->放->V(mutex)->V(full)
消费者：P(full)->P(mutex)->取->V(mutex)->V(empty)
```
