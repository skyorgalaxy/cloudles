# 第1章 计算机系统概述 - 知识点与易错题

> 原书：第1-35页；PDF第12-46页

## 1. 操作系统的概念与目标

操作系统是控制和管理计算机软硬件资源、合理组织工作流程，并为用户和其他软件提供接口与环境的系统软件。

四个视角：

- 资源管理者：管理处理器、存储器、文件和 I/O 设备。
- 用户与硬件的接口：命令接口、程序接口、图形界面。
- 扩充机器：把复杂硬件抽象成易用的虚拟机。
- 控制程序：协调程序执行，防止资源冲突和错误使用。

目标：方便性、有效性、可扩充性、开放性。

## 2. 操作系统的功能

### 处理器管理

进程创建/撤销、调度、同步、通信、死锁处理。

### 存储器管理

内存分配回收、地址转换、存储保护、内存扩充。

### 文件管理

文件创建删除、目录管理、读写、权限和持久化。

### 设备管理

设备分配回收、驱动、缓冲、I/O 控制和设备独立性。

### 用户接口

- 命令接口：联机命令和脱机命令。
- 程序接口：系统调用。
- GUI：图形用户接口。

> [!warning] 库函数不一定是系统调用
> 库函数在用户态提供封装；只有需要内核服务时才通过系统调用进入内核态。

## 3. 操作系统的基本特征

### 并发

两个或多个事件在同一时间间隔内发生。单核上宏观并行、微观交替；并行强调同一时刻真正同时执行。

### 共享

- 互斥共享：一段时间只允许一个进程使用临界资源。
- 同时共享：宏观上允许多个进程共同使用，可表现为交替访问。

并发和共享互为存在条件，是 OS 最基本的特征。

### 虚拟

通过时分复用或空分复用，把一个物理资源抽象成多个逻辑资源，如虚拟处理器、虚拟内存。

### 异步

并发程序以不可预知的速度向前推进，但正确程序的结果应可再现。

## 4. 操作系统发展

| 阶段 | 主要特点 | 主要问题/目标 |
| --- | --- | --- |
| 手工操作 | 无 OS，人工装入运行 | 人机速度矛盾 |
| 单道批处理 | 作业成批、自动连续 | CPU 利用率仍低 |
| 多道批处理 | 多作业驻留，切换运行 | 提高资源利用率和吞吐量，交互性差 |
| 分时系统 | 时间片轮转、多终端 | 及时响应、交互性 |
| 实时系统 | 截止时间约束、高可靠 | 及时性、可靠性 |
| 网络/分布式 | 资源共享与协同 | 透明性、自治性、容错 |

硬实时必须在严格截止时间前完成；软实时偶尔错过截止时间会降低质量但不导致灾难。

## 5. 内核与双重工作模式

CPU 至少提供：

- 用户态/目态：执行普通应用，权限受限。
- 内核态/管态：执行内核，可运行特权指令。

特权指令如修改中断屏蔽、I/O、页表基址等，只能在内核态执行。普通运算、访存等非特权指令可在用户态执行。

### 状态切换

```text
用户态 -> 内核态：中断、异常、系统调用，由硬件完成关键切换
内核态 -> 用户态：执行返回指令，恢复现场
```

用户程序不能通过普通指令自行把状态位改为内核态。

## 6. 中断与异常

### 外中断

来自 CPU 执行指令之外，通常异步：I/O 完成、时钟、外部设备请求。

### 异常/内中断

由当前指令执行引起，通常同步：

- 故障 Fault：可修复后重新执行当前指令，如缺页。
- 自陷 Trap：有意触发，通常执行后返回下一条指令，如系统调用。
- 终止 Abort：严重错误，通常无法恢复。

基本过程：关中断/保护断点和状态 -> 查中断向量 -> 执行处理程序 -> 恢复现场 -> 返回。

> [!warning] 缺页是异常，不是外部 I/O 中断
> 缺页由当前访存指令同步触发；随后磁盘 I/O 完成才可能产生外中断。

## 7. 系统调用

系统调用是应用请求 OS 服务的程序接口，如进程控制、文件、设备、通信和内存管理。

```text
用户程序准备参数
 -> 执行陷入/访管指令
 -> 硬件切换到内核态并定位入口
 -> 内核检查参数并执行服务
 -> 返回用户态
```

系统调用会发生用户态/内核态切换，但不一定发生进程切换；若调用阻塞或被调度，才可能切换进程。

## 8. 操作系统体系结构

| 结构 | 特点 | 优缺点 |
| --- | --- | --- |
| 分层 | 按层次调用下层服务 | 清晰易验证，但层次划分难、效率损失 |
| 模块化 | 按功能模块及接口组织 | 灵活、可扩展，接口管理复杂 |
| 宏内核 | 大量服务运行内核态 | 性能高，内核庞大、故障影响大 |
| 微内核 | 内核只留最基本机制，服务进程化 | 可靠、可扩展，但通信和切换开销大 |
| 外核 | 内核只保护和分配资源，应用自定抽象 | 灵活高效，实现复杂 |

机制回答“提供什么基本能力”，策略回答“如何使用这些能力”；分离有利于灵活性。

## 9. 操作系统引导

典型过程：

```text
通电 -> CPU执行固件中的引导程序
-> 硬件自检 -> 从启动设备读取引导块
-> 引导程序装入OS内核 -> 初始化内核和设备
-> 创建首个用户态进程/服务
```

操作系统内核最初存放在外存，不能说开机前已经在主存。

## 10. 虚拟机

- 第一类虚拟机管理程序：直接运行在硬件上，再承载多个客户 OS。
- 第二类虚拟机管理程序：运行在宿主 OS 上，作为应用承载客户 OS。

虚拟机通过隔离、资源复用和硬件抽象让多个系统共享同一物理机；容器主要共享宿主机内核，不等同于完整硬件虚拟机。

## 高频易错点

- [ ] 把并发和并行当同义词
- [ ] 认为同时共享必须物理同一时刻访问
- [ ] 把库函数一律视为系统调用
- [ ] 认为系统调用一定引起进程切换
- [ ] 用户态可直接执行 I/O 指令
- [ ] 混淆外中断与异常
- [ ] 把缺页当外中断
- [ ] 认为微内核所有服务都在内核态
- [ ] 认为 OS 开机前已驻留主存

## 一页背诵版

```text
OS：资源管理者 + 用户/硬件接口 + 扩充机器
特征：并发、共享、虚拟、异步

用户态->内核态：中断、异常、系统调用
系统调用会切态，不一定切换进程
外中断异步；异常由当前指令同步触发

宏内核：服务多、性能高、内核大
微内核：基本机制少、可靠灵活、通信开销大
```
