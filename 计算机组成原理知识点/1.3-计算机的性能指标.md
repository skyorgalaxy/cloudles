# 1.3 计算机的性能指标

> 原书：第11-16页；PDF第22-27页
>
> 对应内容：1.3 计算机的性能指标
>
> 本节核心：吞吐量与响应时间、主频与时钟周期、CPI/IPC、CPU执行时间、IPS/MIPS、FLOPS、基准程序

## 先建立整体框架

评价计算机性能不能只看主频，也不能只看某个孤立指标。最可靠的主线是：

```text
程序包含多少条指令
  × 每条指令平均需要多少个时钟周期
  × 每个时钟周期持续多长时间
  = 程序的CPU执行时间
```

对应公式：

```text
CPU执行时间 = 指令条数 × 平均CPI × 时钟周期
            = 指令条数 × 平均CPI ÷ 主频
```

三个决定因素分别来自不同方面：

| 因素 | 主要受什么影响 |
| --- | --- |
| 指令条数 | 算法、编程语言、编译器、指令集 |
| 平均CPI | 指令组合、指令集、计算机组成和微体系结构 |
| 主频/时钟周期 | 器件工艺、处理器实现、关键路径 |

> [!tip] 本节最值得记住的一句话
> 比较同一程序在不同机器上的性能，优先比较实际执行时间；主频、CPI、MIPS 都只是影响或描述性能的局部指标。

## 1.3.1 计算机的主要性能指标

### 1. 吞吐量与响应时间

#### 吞吐量

吞吐量表示系统在**单位时间内处理请求的数量**，强调系统整体在一段时间内完成了多少工作。

它可能受到以下环节共同影响：

- 输入数据进入内存的速度；
- CPU 取指、执行指令的速度；
- 数据在内存中读写的速度；
- 结果输出到外部设备的效率。

主存常处在数据交换的关键位置，因此其性能会显著影响系统吞吐量。

#### 响应时间

响应时间是从用户发出一个请求，到系统返回所需结果为止的**总等待时间**。

通常包括：

```text
响应时间 = CPU时间 + 各类等待时间
```

等待时间可能来自磁盘访问、内存访问、I/O 操作、排队、操作系统调度等。

> [!warning] CPU执行时间不等于响应时间
> CPU执行时间只统计 CPU 真正为该程序工作的时间；响应时间还包含 I/O 和其他等待时间。优化 CPU 并不会等比例缩短整段响应时间。

#### 两者的关注点

| 指标 | 关注的问题 | 典型场景 |
| --- | --- | --- |
| 响应时间 | 单个任务多久完成 | 个人程序、交互请求 |
| 吞吐量 | 单位时间完成多少任务 | 服务器、批处理系统 |

增加处理器数量通常更容易提高吞吐量；若任务不能并行，单个任务的响应时间未必明显缩短。

---

### 2. 时钟周期与主频

#### CPU 时钟周期

CPU 时钟周期是机器内部主时钟脉冲的宽度，是 CPU 工作的最小时间单位。

时钟周期通常根据组合逻辑电路的最大延迟确定；在流水线处理器中，通常由最慢流水段及额外开销限制。

常用单位：

```text
s、ms、μs、ns、ps
```

#### 主频

主频又称 CPU 时钟频率，表示每秒包含多少个时钟周期，单位是 Hz。

```text
主频 = 1 ÷ 时钟周期
时钟周期 = 1 ÷ 主频
```

常用换算：

```text
1MHz = 10^6Hz
1GHz = 10^9Hz

1ms = 10^-3s
1μs = 10^-6s
1ns = 10^-9s
1ps = 10^-12s
```

例：主频为 `2GHz`，则时钟周期为：

```text
T = 1 / (2 × 10^9) s = 0.5ns
```

> [!warning] 主频高不代表整机一定更快
> 只有在指令条数和 CPI 等其他条件相同或可比时，提高主频才会缩短 CPU 执行时间。不同 ISA、不同微体系结构的处理器不能只比较主频。

---

### 3. CPI 与 IPC

#### CPI

CPI（Cycles Per Instruction）表示执行一条指令平均需要的时钟周期数。

不同类型的指令可能具有不同 CPI。对一个程序而言，平均 CPI 是各种指令 CPI 按其动态执行比例计算的加权平均值：

```text
平均CPI = Σ(第i类指令条数 × 第i类CPI) ÷ 总指令条数
        = Σ(第i类指令比例 × 第i类CPI)
```

例：某程序中三类指令的比例依次为 50%、30%、20%，CPI 依次为 1、2、4，则：

```text
平均CPI = 0.5×1 + 0.3×2 + 0.2×4 = 1.9
```

> [!warning] 必须按指令条数加权
> 若各类指令数量不同，不能直接对各类 CPI 求算术平均。

#### IPC

IPC（Instructions Per Cycle）表示平均每个时钟周期执行的指令条数。

在同一统计口径下：

```text
IPC = 1 ÷ CPI
CPI = 1 ÷ IPC
```

一般来说，CPI 越低或 IPC 越高越好，但仍要结合主频和指令条数判断实际执行时间。

> [!warning] 主频通常不决定 CPI
> 主频改变每个时钟周期的长短；CPI 表示一条指令占用多少个周期。教材题中，系统结构、指令集和计算机组成会影响 CPI，而主频本身不改变 CPI。

### 4. CPU 执行时间

#### 核心公式组

设：

- `IC`：程序动态执行的指令条数；
- `CPI`：平均每条指令所需时钟周期数；
- `f`：CPU 主频；
- `T`：时钟周期，`T = 1/f`。

则：

```text
CPU时钟周期数 = IC × CPI

CPU执行时间 = CPU时钟周期数 × T
            = IC × CPI × T
            = IC × CPI ÷ f
```

若已知各类指令条数与各自 CPI，也可直接计算：

```text
CPU时钟周期数 = Σ(IC_i × CPI_i)
CPU执行时间 = Σ(IC_i × CPI_i) ÷ f
```

#### 性能与执行时间

当用执行时间衡量性能时：

```text
性能 ∝ 1 ÷ 执行时间
```

机器 B 相对机器 A 的加速比：

```text
加速比 = A的执行时间 ÷ B的执行时间
```

若 A 运行需 20s，B 运行需 16s，则：

```text
B相对A的加速比 = 20/16 = 1.25
```

即 B 的速度是 A 的 1.25 倍；也可以说 B 的执行时间比 A 少 20%，不能说“少 1.25 倍”。

#### 解题通用步骤

```text
1. 统一 Hz、s、ns 等单位
2. 求总指令条数或各类指令比例
3. 求平均CPI或总时钟周期数
4. 用 CPU时间 = IC×CPI÷主频
5. 若比较性能，再对执行时间取倒数或作比
```

#### 典型变化分析

若原程序执行时间为：

```text
t_old = IC_old × CPI_old ÷ f_old
```

优化后为：

```text
t_new = IC_new × CPI_new ÷ f_new
```

则：

```text
t_new / t_old
= (IC_new/IC_old) × (CPI_new/CPI_old) × (f_old/f_new)
```

这个比值小于 1，优化才真正缩短了 CPU 执行时间。

例：编译优化后指令条数变为原来的 70%，但 CPI 变为原来的 1.2 倍，主频不变：

```text
t_new/t_old = 0.7 × 1.2 = 0.84
```

若原来用时 20s，则优化后用时：

```text
20 × 0.84 = 16.8s
```

> [!tip] 不必分别求出所有未知量
> 许多比例题可直接对 `IC × CPI ÷ f` 的新旧值作比，计算更快，也更不容易丢失单位。

### 5. IPS、MIPS 与 GIPS

#### IPS

IPS（Instructions Per Second）表示每秒执行的指令条数：

```text
IPS = 指令条数 ÷ CPU执行时间
    = 主频 ÷ 平均CPI
```

#### MIPS

MIPS（Million Instructions Per Second）表示每秒执行多少百万条指令：

```text
MIPS = 指令条数 ÷ (CPU执行时间 × 10^6)
     = 主频 ÷ (平均CPI × 10^6)
```

若主频直接以 MHz 为单位代入，则数值上：

```text
MIPS = 主频(MHz) ÷ 平均CPI
```

例：主频为 `1.5GHz`，平均 CPI 为 `1.2`：

```text
IPS  = 1.5×10^9 ÷ 1.2 = 1.25×10^9 条/s
GIPS = 1.25
MIPS = 1250
```

#### MIPS 的局限性

MIPS 不适合直接比较指令集不同的机器，因为：

- 不同 ISA 中“一条指令”完成的工作量不同；
- 同一高级语言程序在不同 ISA 上生成的指令条数可能不同；
- CPI 和指令组合也不同；
- MIPS 高不一定意味着完成同一任务所需时间短。

> [!warning] 最终仍应比较完成同一任务的时间
> MIPS 衡量的是“每秒执行多少条指令”，不是“每秒完成多少个同样的程序”。指令更简单的机器可能 MIPS 很高，却需要执行更多指令。

### 6. FLOPS 及数量级

FLOPS（Floating-point Operations Per Second）表示每秒执行的浮点运算次数，常用于评价科学计算、高性能计算和超级计算机的浮点运算能力。

| 名称 | 含义 | 数量级 |
| --- | --- | ---: |
| MFLOPS | 每秒百万次浮点运算 | `10^6` |
| GFLOPS | 每秒十亿次浮点运算 | `10^9` |
| TFLOPS | 每秒万亿次浮点运算 | `10^12` |
| PFLOPS | 每秒千万亿次浮点运算 | `10^15` |
| EFLOPS | 每秒百亿亿次浮点运算 | `10^18` |
| ZFLOPS | 每秒十万亿亿次浮点运算 | `10^21` |

例：`93.0146 PFLOPS` 表示每秒约完成：

```text
93.0146 × 10^15 ≈ 9.3 × 10^16 次浮点运算
```

#### MIPS 与 FLOPS 的区别

| MIPS | FLOPS |
| --- | --- |
| 每秒执行的百万条指令数 | 每秒完成的浮点运算次数 |
| 受指令集和指令复杂度影响大 | 更适合描述浮点计算能力 |
| 不同 ISA 间通常不宜直接比较 | 科学计算中较常用 |

> [!warning] FLOPS 不是“浮点指令条数”
> 一条浮点指令可能完成一次或多次浮点运算，尤其在向量、SIMD 和融合乘加场景中，指令数与浮点操作数不一定相等。

### 7. 数量单位：二进制与十进制前缀

教材和统考中通常按以下习惯处理：

| 场景 | K/k、M、G、T 的常见含义 |
| --- | --- |
| 存储容量、文件大小 | 常按 `2` 的幂次，如 `1KB = 2^10B` |
| 速率、频率 | 常按 `10` 的幂次，如 `1GHz = 10^9Hz`、`1kb/s = 10^3b/s` |

还应注意：

```text
b = bit（位）
B = Byte（字节）
1B = 8b
```

> [!warning] 先看对象，再解释前缀
> 不能看到 K、M、G 就固定按 `2` 的幂或固定按 `10` 的幂。题目给出明确标准时，以题目为准。

### 8. 基准程序

基准程序（Benchmark）是一组专门用于性能评测的典型程序。通过让不同机器运行相同的基准程序并比较执行时间，可以较客观地评价系统性能。

好的基准测试应尽量贴近真实应用负载，而不只是针对某一个局部硬件指标。

#### 基准程序的局限

- 性能可能依赖少数关键代码片段；
- 硬件或编译器可能专门针对这些片段优化；
- 对基准程序表现好，不代表对所有真实工作负载都好；
- 应结合具体应用领域选择合适的测试集，并综合多个指标判断。

## 四组必须会区分的概念

### 响应时间与 CPU 执行时间

```text
响应时间 = CPU时间 + I/O及其他等待时间
```

只提升 CPU 的速度时，等待时间不变，因此总响应时间不会按 CPU 加速比例等比例下降。

例：某程序总响应时间为 100s，其中 CPU 时间 90s、I/O 时间 10s。若 CPU 速度提高 50%，即变为原来的 1.5 倍：

```text
新CPU时间 = 90/1.5 = 60s
新响应时间 = 60 + 10 = 70s
```

### 主频与运算速度

主频只表示每秒有多少个时钟周期。程序运行速度还取决于指令条数与 CPI：

```text
CPU执行时间 = IC × CPI ÷ 主频
```

因此，跨处理器比较时不能只看 GHz。

### CPI 与时钟周期

| CPI | 时钟周期 |
| --- | --- |
| 一条指令平均占多少个周期 | 一个周期持续多长时间 |
| 无量纲 | 单位为时间 |
| 受指令集、组成和指令组合影响 | 与主频互为倒数 |

### “快几倍”与“时间减少百分之几”

若 B 的速度是 A 的 `k` 倍，则：

```text
t_B = t_A / k
```

执行时间减少比例为：

```text
1 - 1/k
```

例如速度提高到原来的 1.25 倍，执行时间变为原来的 0.8，即减少 20%。

## 统考真题考点速查

| 年份 | 考点 | 关键结论 |
| ---: | --- | --- |
| 2010 | 提高系统性能的措施 | 提主频、优化数据通路、编译优化都可能缩短执行时间 |
| 2011 | 浮点运算速度指标 | MFLOPS |
| 2012 | CPU 加速但 I/O 不变 | 分别计算 CPU 时间与 I/O 时间，最后相加 |
| 2013 | 主频、时钟周期与 MIPS | `MIPS = 主频/(CPI×10^6)` |
| 2014 | 指令条数与 CPI 同时变化 | 按 `IC×CPI` 的新旧比例计算 |
| 2017 | 同 ISA 下比较执行时间 | 指令条数相同，比较 `CPI/主频` |
| 2019 | 时钟脉冲与时钟周期 | 时钟周期是主频的倒数 |
| 2021 | PFLOPS 数量级 | `1PFLOPS = 10^15 FLOPS` |
| 2022 | 加权平均 CPI 与 CPU 时间 | 先按指令比例求 CPI，再算 `IC×CPI/f` |
| 2023 | IPS 与 CPU 时间 | `IPS=f/CPI`，时间为 `IC/IPS` |

## 高频易错点总清单

- [ ] 把响应时间与 CPU 执行时间视为同一个概念
- [ ] 认为提高 CPU 速度会等比例缩短含 I/O 等待的总时间
- [ ] 只看主频就断定哪台计算机更快
- [ ] 把时钟周期与主频理解成同方向变化
- [ ] 把 CPI 解释成一条指令所用的频率
- [ ] 认为主频越高，CPI 就一定越小
- [ ] 直接对各类指令 CPI 求算术平均，忽略指令比例
- [ ] 忘记 `IPC = 1/CPI`
- [ ] 在 `CPU时间 = IC×CPI/f` 中漏掉任一因素
- [ ] 比例题中混淆新旧主频的分子位置
- [ ] 把速度提高 25% 说成执行时间减少 25%
- [ ] 把 MIPS 当作不同 ISA 机器间绝对可靠的性能指标
- [ ] 把 FLOPS 误写成每秒执行的浮点指令数
- [ ] 混淆 MHz、GHz 与 ns、μs 的数量级
- [ ] 不区分存储容量中的 `2` 的幂和频率/速率中的 `10` 的幂
- [ ] 把针对基准程序的高性能直接推广到所有应用

## 一页背诵版

```text
吞吐量：单位时间处理的请求数量
响应时间：请求发出到结果返回的总时间
响应时间 = CPU时间 + 等待时间

主频 f = 1/时钟周期 T
CPI：平均每条指令使用的时钟周期数
IPC = 1/CPI

平均CPI = Σ(指令比例 × 该类CPI)
总时钟周期数 = 指令条数IC × 平均CPI
CPU执行时间 = IC × CPI × T = IC × CPI / f

性能与执行时间成反比
加速比 = 原执行时间 / 新执行时间

IPS = f/CPI
MIPS = f/(CPI×10^6)

MFLOPS 10^6
GFLOPS 10^9
TFLOPS 10^12
PFLOPS 10^15
EFLOPS 10^18
ZFLOPS 10^21

比较同一任务：实际执行时间最可靠
跨ISA比较：不能只看主频或MIPS
```

## 学完后的自测

1. 用一句话分别解释吞吐量和响应时间。
2. 说明为什么 CPU 执行时间通常小于程序的响应时间。
3. 主频为 2.5GHz 时，时钟周期是多少 ns？
4. 某程序两类指令比例为 70% 和 30%，CPI 分别为 1 和 4，求平均 CPI。
5. 某程序执行 `5×10^8` 条指令，平均 CPI 为 1.5，主频为 3GHz，求 CPU 执行时间。
6. 用一句话说明为什么不能只凭主频比较两台处理器。
7. 写出 IPS 和 MIPS 的公式，并说明 MIPS 跨 ISA 比较的缺陷。
8. 解释 1 PFLOPS 表示什么，并换算为每秒浮点运算次数。
9. 程序总时间 80s，其中 CPU 时间 60s。CPU 速度提高到原来的 2 倍，其他时间不变，新总时间是多少？
10. 某优化使指令条数变为 80%、CPI 变为 90%、主频变为 120%，求新旧 CPU 时间之比。

### 自测答案

3. `1/(2.5×10^9)s = 0.4ns`。
4. `0.7×1 + 0.3×4 = 1.9`。
5. `(5×10^8×1.5)/(3×10^9) = 0.25s`。
8. 每秒 `10^15` 次浮点运算。
9. `60/2 + 20 = 50s`。
10. `0.8×0.9/1.2 = 0.6`，新时间为原来的 60%，即缩短 40%。

若能独立完成以上计算，并能说清主频、CPI、指令条数各自的作用，本节就已经掌握。
