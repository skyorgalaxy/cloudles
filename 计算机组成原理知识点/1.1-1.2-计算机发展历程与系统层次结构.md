## 先建立整体框架

这两节不需要死记大量年代。真正要建立的是下面这条主线：

```text
人要解决问题
  -> 设计算法
  -> 用高级语言写成源程序
  -> 翻译成机器指令
  -> 指令和数据预先存入主存
  -> CPU不断取指、译码、执行
  -> 硬件最终完成运算和输入/输出
```

整个计算机系统可从三个角度理解：

1. **组成角度**：硬件 + 软件。
2. **结构角度**：CPU、存储器、输入设备、输出设备和总线。
3. **层次角度**：应用、算法与语言、操作系统、ISA、微体系结构、数字逻辑与电路。

> [!tip] 这两节最值得记住的一句话
> 冯·诺依曼机以“存储程序”为核心，ISA 是软件与硬件的接口，CPU 通过反复执行“取指—译码—执行”来运行程序。

## 1.1 计算机发展历程

### 1.1.1 计算机硬件的发展

#### 计算机的四代变化

划分四代计算机的最主要依据是**逻辑元件**的变化。

| 代次 | 大致年代 | 主要逻辑元件 | 典型特点 |
| --- | --- | --- | --- |
| 第一代 | 1946-1957 | 电子管 | 机器语言编程；延迟线或磁鼓；体积大、成本高、速度低 |
| 第二代 | 1958-1964 | 晶体管 | 磁芯存储器；出现高级语言及编译程序；操作系统出现雏形 |
| 第三代 | 1965-1971 | 中小规模集成电路 | 半导体存储器逐渐取代磁芯；高级语言普及；分时操作系统出现 |
| 第四代 | 1972年至今 | 大规模、超大规模集成电路 | 微处理器诞生；并行、流水线、Cache、虚拟存储器等技术广泛应用 |

记忆主线：

```text
电子管 -> 晶体管 -> 中小规模集成电路 -> 大/超大规模集成电路
```

> [!warning] 易错点
> 四代计算机是按逻辑元件划分的，不是按操作系统、编程语言或存储器划分的。

#### 摩尔定律

在价格不变的前提下，集成电路上可容纳的晶体管数量约每 **18个月** 翻一番，因此处理器的理论性能潜力也快速提高。

考试中通常考概念判断，不必把它理解成任何程序的实际运行速度都会严格每18个月翻倍。系统性能还受存储器、I/O、软件和并行性等因素限制。

#### 半导体存储器的发展

早期主存经历了延迟线、磁鼓、磁芯存储器，后来逐步转向半导体存储器。单芯片存储容量大致沿着：

```text
1KB -> 4KB -> 16KB -> 64KB -> 256KB -> 1MB -> ... -> GB/TB级
```

发展的总体趋势是：容量增大、速度提高、单位成本下降。

#### 微处理器与机器字长

微处理器从早期的 Intel 4004 逐步发展到 8位、16位、32位、64位处理器。

机器字长简称**字长**，通常指 CPU 通用寄存器的宽度。它主要影响：

- 一次整数运算能够处理的数据位数；
- 可直接表示的数据范围；
- 与地址相关的体系结构能力。

> [!warning] 字长不等于地址总线宽度
> “64位处理器”通常强调通用寄存器和整数运算宽度，不能据此机械地断言其实际物理地址总线一定也是64位。

### 1.1.2 计算机软件的发展

软件发展的两条主线：

- **编程语言**：机器语言、汇编语言逐步发展到更接近人类表达方式的高级语言。
- **系统软件**：操作系统、语言处理程序、数据库管理系统等逐渐完善。

典型高级语言：

| 语言 | 典型侧重 |
| --- | --- |
| FORTRAN | 科学与工程计算 |
| Pascal | 结构化程序设计 |
| C++ | 面向对象程序设计 |
| Java | 跨平台应用 |

软件的进步降低了使用硬件的门槛，也提高了硬件资源的利用效率。

## 1.2 计算机系统层次结构

### 1.2.1 计算机系统的组成

一个完整的计算机系统包括：

```text
计算机系统 = 硬件系统 + 软件系统
```

- **硬件**：有形的物理设备和部件。
- **软件**：在硬件上运行的程序，以及与程序相关的数据和文档。

二者缺一不可。只有硬件没有软件，机器无法方便地完成用户任务；只有软件没有硬件，程序也没有执行载体。

#### 软硬件功能边界

同一种逻辑功能有时既可用硬件实现，也可用软件实现，这称为**软/硬件逻辑功能的等价性**。

例如，浮点运算可以由专用浮点运算硬件完成，也可以由软件程序模拟。在输入输出和数值规范相同时，两种实现应得到相同结果，但通常：

| 硬件实现 | 软件实现 |
| --- | --- |
| 速度快 | 灵活、容易修改 |
| 成本可能更高 | 开发成本通常较低 |
| 设计完成后不易改变 | 通常效率较低 |

一般而言，使用频繁且适合固化的功能更倾向于用硬件实现。最终如何划分要综合考虑性能、成本和技术可行性。

### 1.2.2 计算机硬件

#### 冯·诺依曼机的基本思想

冯·诺依曼在研究 EDVAC 时提出“存储程序”思想。基于该思想的计算机具有以下特征：

1. 采用**存储程序**工作方式：程序和初始数据预先存入主存，启动后自动、连续地取指和执行。
2. 硬件由运算器、控制器、存储器、输入设备和输出设备五大部件组成。
3. 指令和数据以相同形式存放在存储器中，形式上无法区分，但计算机能根据取出位置和执行阶段识别其用途。
4. 指令和数据均采用二进制编码。
5. 指令由操作码和地址码组成：操作码指出“做什么”，地址码指出“对谁做”。

一句话概括：

```text
把程序当作数据一样事先存入存储器，再由CPU按地址自动取出并执行。
```

> [!warning] 三个高频误区
>
> - 存储程序强调先把程序和数据放入**主存**，不是让 CPU 直接从磁盘逐条执行。
> - 指令和数据形式上都由二进制表示，并不代表二者的含义相同。
> - 地址码不一定直接给出操作数本身，也可能给出操作数地址或形成地址所需的信息。

#### 五大部件与现代结构

```text
输入设备 -> 存储器 <-> 运算器 -> 输出设备
                  ^
                控制器
```

现代计算机通常把运算器、控制器和各类寄存器集成在 CPU 内：

```text
CPU = 数据通路 + 控制单元
数据通路的核心 = ALU + 通用寄存器组
```

##### CPU

- **ALU（算术逻辑单元）**：完成算术运算和逻辑运算。
- **通用寄存器组**：给 ALU 提供操作数，暂存运算结果，实现高速数据访问。
- **数据通路**：还包括多路选择器和内部互连通路等，负责在 CPU 各部件间传送并处理数据。
- **控制单元**：取出并译码指令，根据指令含义产生控制信号，协调数据通路按正确时序工作。

> [!warning] ALU 不只做算术运算
> “与、或、非、异或、移位、比较”等逻辑操作也由 ALU 完成。

##### 存储器

按访问特性可分为：

- **内存**：现代语境常包括主存和 Cache；传统教材中的“内存”有时专指主存。
- **外存**：磁盘、固态硬盘等可与主存交换数据；磁带、光盘等也可用于长期备份。

在存储程序结构中，主存用于保存当前要执行的程序和数据。CPU 能直接访问的是主存和寄存器，不能把磁盘当作主存直接执行其中的普通指令。

##### 外部设备和设备控制器

外设通常由两部分构成：

- 物理功能部件，如键盘、鼠标、显示器、打印头；
- 设备控制器，也称 I/O 控制器或 I/O 接口，负责与主机通信并控制实际设备。

例如，USB 控制器、显卡和网卡都可看作设备控制器。

##### 总线

总线是各部件之间传送信息的公共通路。CPU、主存和 I/O 接口通过总线互连，传送数据、地址和控制信息。

### 1.2.3 计算机软件

#### 系统软件和应用软件

| 类型 | 作用 | 典型例子 |
| --- | --- | --- |
| 系统软件 | 管理和调度资源，为用户及应用程序提供基础服务 | 操作系统、DBMS、语言处理程序、标准库、网络与分布式系统、服务程序 |
| 应用软件 | 解决某个具体应用领域的问题 | 办公、科学计算、工程设计、数据统计、信息处理软件 |

判断方法：看它主要是在**管理计算机并提供公共基础服务**，还是直接解决**特定用户问题**。

### 1.2.4 计算机系统的层次结构

计算机系统通过逐层抽象隐藏底层细节。每一层向上提供较简洁的接口，向下依赖下一层实现。

```text
应用（问题）                 <- 最终用户
算法与编程                   <- 应用程序员
操作系统 / 虚拟机
指令集体系结构 ISA           <- 软件与硬件的交界
微体系结构
功能部件 / RTL
电路与器件                   <- 电子工程师
```

#### 编程语言

| 语言 | 表示方式 | 硬件能否直接执行 | 与机器结构的关系 |
| --- | --- | --- | --- |
| 机器语言 | 0、1组成的机器指令 | 能 | 完全相关 |
| 汇编语言 | `mov`、`add` 等助记符 | 不能，须经汇编 | 与特定机器结构密切相关 |
| 高级语言 | 接近自然语言和数学表达 | 不能，须编译或解释 | 相对独立于底层结构 |

只有机器语言程序能被硬件直接识别和执行。

> [!warning] 汇编指令不是机器指令
> 二者通常在语义上基本一一对应，但汇编指令是符号表示，仍须经过汇编器转换成二进制机器指令。

#### 翻译程序的三种类型

| 翻译程序 | 输入 | 输出与执行方式 |
| --- | --- | --- |
| 汇编程序（汇编器） | 汇编语言源程序 | 生成机器语言目标程序 |
| 编译程序（编译器） | 高级语言源程序 | 一次性翻译成汇编语言或机器语言目标程序 |
| 解释程序（解释器） | 高级语言源程序 | 逐句翻译、立即执行，通常不生成独立目标程序 |

典型比较：

- 编译：翻译过程较长，生成目标程序后通常运行较快。
- 解释：实现和调试较灵活，但边翻译边执行通常较慢。

#### 操作系统

操作系统对硬件及底层结构进行抽象，管理和调度处理器、内存与 I/O 等资源，并向程序提供运行环境。可以把它看成向上提供的一台“操作系统虚拟机”。

#### ISA：软件与硬件的关键接口

ISA（Instruction Set Architecture，指令集体系结构）从程序员和编译器的角度，规定软件可以直接使用哪些硬件功能，主要包括：

- 指令格式；
- 操作类型；
- 寻址方式；
- 软件可访问的寄存器等硬件资源。

因此，ISA 是**软件可见的硬件接口**：

```text
ISA规定“能做什么”
微体系结构决定“具体怎么做”
```

#### 微体系结构

微体系结构又称微架构，是处理器内部实现某个 ISA 的硬件组织方式，包括：

- 数据通路组织；
- 控制单元实现；
- 流水线级数；
- Cache 层次；
- 分支预测；
- 运算部件的具体设计。

同一个 ISA 可以有多种微体系结构。例如，不同代 x86 处理器可运行同一 ISA 的程序，但内部流水线、Cache、执行单元等实现差异很大。

> [!tip] 兼容性的核心
> 只要处理器遵守同一 ISA，原有机器语言程序通常无需修改即可运行；微体系结构可以继续演进，以提高性能或降低功耗。

### 1.2.5 计算机系统的不同用户

| 用户角色 | 主要工作层次 |
| --- | --- |
| 最终用户 | 通过应用程序和操作系统界面完成任务 |
| 系统管理员 | 安装和维护软硬件、管理用户、备份数据、升级系统 |
| 应用程序员 | 使用高级语言开发面向用户的应用软件 |
| 系统程序员 | 开发操作系统、编译器、DBMS 等系统软件，直接面向 ISA |

层次结构的价值在于让上层用户不必了解全部底层细节。例如，应用程序员通常无须知道某条指令的晶体管级实现。

### 1.2.6 计算机系统的工作原理

#### “存储程序”工作方式

程序执行前，先将指令和数据装入主存。运行后，CPU 自动逐条取出并执行指令，直到程序结束。

一条指令的抽象执行过程：

```text
根据PC取指 -> 指令译码 -> 取操作数 -> 执行 -> 写回结果 -> 取下一条指令
```

#### 程序计数器 PC

PC 保存**下一条将要执行的指令地址**。

- 顺序执行时：`PC <- 当前PC + 指令长度`；
- 执行跳转指令时：`PC <- 指令指定的目标地址`。

随后 CPU 再根据更新后的 PC 取下一条指令，从而形成连续或跳转的控制流。

> [!warning] PC 中存的是地址，不是指令本身
> CPU 使用 PC 给出的地址访问主存并取出指令。

#### 从 C 源程序到可执行文件

以 GCC 工具链为例：

```text
hello.c
  -> 预处理 cpp -> hello.i
  -> 编译 ccl   -> hello.s
  -> 汇编 as    -> hello.o
  -> 链接 ld    -> hello（可执行文件）
```

| 阶段 | 主要工作 | 典型输出 |
| --- | --- | --- |
| 预处理 | 展开 `#include`、宏和条件编译等预处理指令 | 修改后的源程序，文本 |
| 编译 | 把高级语言转换为汇编语言 | 汇编源程序，文本 |
| 汇编 | 把汇编指令转换为机器指令 | 可重定位目标文件，二进制 |
| 链接 | 合并目标文件和所需库，解析外部符号 | 可执行目标文件，二进制 |

> [!warning] 编译与链接不能颠倒
> 统考默认流程是“预处理 -> 编译 -> 汇编 -> 链接”。`printf` 等库函数的外部符号通常在链接阶段解析。

#### 指令执行的简要模型

可执行文件中的代码段由机器指令构成。CPU 可把指令执行抽象为经典的：

```text
取指 -> 译码 -> 执行
```

这个模型说明硬件在做什么；至于控制器、数据通路和时序信号具体怎样实现，将在后续 CPU 章节展开。

## 三组必须会区分的概念

### 指令与数据

| 指令 | 数据 |
| --- | --- |
| 告诉 CPU 做什么操作 | 是操作对象或运算结果 |
| 通常由操作码和地址信息组成 | 可表示数值、字符、地址等 |
| 在存储器中也是二进制 | 在存储器中同样是二进制 |

二者不能单靠某串二进制本身的外观判断，要结合 CPU 当前的取用方式和上下文。

### ISA 与微体系结构

| ISA | 微体系结构 |
| --- | --- |
| 软件可见 | 大部分实现细节对软件不可见 |
| 规定指令、寄存器、寻址方式等 | 规定流水线、Cache、数据通路等 |
| 回答“机器能做什么” | 回答“硬件怎样实现” |
| 相同 ISA 保证二进制兼容的基础 | 同一 ISA 可有不同实现 |

### 编译、汇编、解释

```text
高级语言 --编译--> 汇编语言/机器语言
汇编语言 --汇编--> 机器语言
高级语言 --解释--> 逐句翻译并立即执行
```

机器只能直接执行机器语言；汇编语言虽然很接近机器语言，仍不能直接执行。

## 高频易错点总清单

- [ ] 把四代计算机按编程语言或操作系统划分
- [ ] 把摩尔定律理解成任何程序性能都固定每18个月翻倍
- [ ] 把“64位处理器”直接等同于64位物理地址总线
- [ ] 认为完整计算机系统只包括硬件或只包括主机
- [ ] 认为 ALU 只做算术运算，不做逻辑运算
- [ ] 把外部设备与设备控制器混为一谈
- [ ] 认为 CPU 从磁盘逐条取指执行
- [ ] 认为指令和数据用不同进制表示
- [ ] 认为汇编语言能被硬件直接执行
- [ ] 认为汇编语言与机器结构无关
- [ ] 认为解释程序会先生成完整、独立的目标程序
- [ ] 混淆 ISA 与微体系结构
- [ ] 认为同一 ISA 只能由一种微体系结构实现
- [ ] 认为一条高级语言语句必然只对应一条机器指令
- [ ] 把 PC 的内容说成当前指令或指令本身，而不是下一条指令地址
- [ ] 写错“预处理 -> 编译 -> 汇编 -> 链接”的顺序
- [ ] 认为 `printf` 等外部库函数在预处理阶段完成链接

## 一页背诵版

```text
完整计算机系统 = 硬件系统 + 软件系统

冯·诺依曼机：
1. 存储程序
2. 五大部件：运算器、控制器、存储器、输入设备、输出设备
```

## 学完后的自测

1. 不看笔记，说出冯·诺依曼机的五个特征。
2. 画出五大部件，并说明现代 CPU 由哪些部分构成。
3. 分别解释 ALU、控制单元、主存、I/O 控制器和总线的作用。
4. 举例说明一个功能为什么既可由软件实现，也可由硬件实现。
5. 用一句话区分 ISA 和微体系结构。
6. 解释为什么汇编语言不能由硬件直接执行。
7. 默写 C 程序生成可执行文件的四阶段及每阶段输出。
8. 说明顺序指令和跳转指令执行后，PC 分别怎样更新。

若以上 8 题能独立答出，这两节的核心就已经掌握。
