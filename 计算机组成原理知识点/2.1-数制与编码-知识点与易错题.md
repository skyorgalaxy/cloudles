> 本节核心：进制转换、定点数编码、补码范围、C 整数转换、位扩展与截断

## 1. 进位计数制

### 1.1 基本规则

r 进制数使用 `0 ~ r-1` 共 r 个数码，每一位的权为 r 的整数次幂：

```text
(K_n...K_0.K_-1...K_-m)_r = Σ(K_i × r^i)
```

常用进制：

| 进制 | 基数 | 数码 | 计数规则 |
| --- | ---: | --- | --- |
| 二进制 | 2 | 0、1 | 逢二进一 |
| 八进制 | 8 | 0-7 | 逢八进一 |
| 十进制 | 10 | 0-9 | 逢十进一 |
| 十六进制 | 16 | 0-9、A-F | 逢十六进一 |

### 1.2 二进制、八进制与十六进制

二进制与八/十六进制可直接分组转换：

```text
1位八进制 <-> 3位二进制
1位十六进制 <-> 4位二进制
```

从小数点向两侧分组，不足位补 0：整数部分在高位侧补，小数部分在低位侧补。

例：

```text
(111000010.01101)2
= (111 000 010 . 011 010)2
= (702.32)8

= (0001 1100 0010 . 0110 1000)2
= (1C2.68)16
```

### 1.3 任意进制转十进制

按权展开：

```text
(1011.11)2
= 1×2^3 + 0×2^2 + 1×2^1 + 1×2^0
  + 1×2^-1 + 1×2^-2
= 11.75
```

### 1.4 十进制转任意进制

- 整数部分：除基取余，余数从下往上读。
- 小数部分：乘基取整，整数从上往下读。

有限十进制小数不一定能用有限二进制小数精确表示。例如 `0.1` 的二进制表示无限循环。

> [!warning] 小数转换何时停止
> 题目若规定机器位数或精度，达到位数后按题意截断或舍入；不能因为小数部分未变成 0 就无限计算。

## 2. 定点数的编码表示

### 2.1 定点小数与定点整数

小数点位置是约定的，不真正存入机器：

```text
定点小数：符号位 | 小数数值位
定点整数：符号位 | 整数数值位 | 约定小数点
```

若机器字长为 n+1 位，其中 1 位符号位、n 位数值位，则编码总宽度为 n+1 位。

### 2.2 原码

原码用最高位表示符号，`0` 为正，`1` 为负，其余位表示绝对值。

```text
[+x]原 = 0 | x的绝对值
[-x]原 = 1 | x的绝对值
```

范围：

```text
定点整数：-(2^n-1) ~ +(2^n-1)
定点小数：-(1-2^-n) ~ +(1-2^-n)
```

特点：直观、乘除时符号和数值可分开处理，但加减前要比较绝对值；存在 `+0` 和 `-0`。

### 2.3 反码

- 正数反码与原码相同。
- 负数反码：符号位不变，数值位按位取反。

反码同样有 `+0` 和 `-0`，范围与原码相同，通常作为理解补码的过渡表示。

### 2.4 补码

- 正数补码与原码相同。
- 负数补码：原码数值位取反加 1；等价地，对完整机器数按位取反再加 1。

```text
[-x]补 = NOT([+x]补) + 1
```

n+1 位补码整数范围：

```text
-2^n ~ 2^n-1
```

n 位补码整数范围：

```text
-2^(n-1) ~ 2^(n-1)-1
```

补码的关键性质：

1. `0` 的表示唯一。
2. 符号位与数值位一起参与运算。
3. 减法可转换为加法：`[A-B]补 = [A]补 + [-B]补`。
4. 运算结果自动舍弃超出字长的最高进位，按模 `2^n` 工作。
5. 最小负数 `100...0` 没有可表示的相反数；对它求负仍得到自身并发生溢出。

#### 补码快速求真值

对负补码可用两种方法：

```text
方法一：按位取反加1，得到绝对值，再添负号
方法二：符号位权为 -2^(n-1)，其余位按正常权相加
```

例如 8 位补码 `10011011`：

```text
-2^7 + 2^4 + 2^3 + 2^1 + 2^0 = -101
```

#### 补码大小比较

- 符号不同：正数大于负数。
- 都为正：按无符号数比较。
- 都为负：补码按无符号值比较时，补码越大，真值通常也越大；更稳妥的方法是先还原真值或使用有符号比较电路规则。

> [!warning] “负数数值位越大，绝对值越大”不适用于补码位串
> 原码数值位可直观看绝对值；补码应按权解释或求补还原。

### 2.5 移码

移码常用于表示浮点数的阶码。若编码共 n+1 位、偏置值为 `2^n`：

```text
[x]移 = 2^n + x，-2^n <= x < 2^n
```

对于同一位宽的整数，移码与补码只有最高位相反：

```text
[x]移 = [x]补 的符号位取反
```

移码特点：

- `0` 的表示唯一；
- 全 0 表示最小值，全 1 表示最大值；
- 机器码按无符号大小排序，与真值大小顺序一致，便于比较阶码；
- IEEE 754 使用的偏置值是 `2^(k-1)-1`，与上述教材移码偏置并不完全相同。

### 2.6 四种编码对照

| 项目 | 原码 | 反码 | 补码 | 移码 |
| --- | --- | --- | --- | --- |
| 正数 | 符号0，数值不变 | 同原码 | 同原码 | 补码最高位取反 |
| 负数 | 符号1，绝对值 | 原码数值位取反 | 反码加1 | 补码最高位取反 |
| 零 | 两种 | 两种 | 唯一 | 唯一 |
| 主要用途 | 直观表示、部分乘除 | 过渡理解 | 定点整数和加减运算 | 浮点阶码 |

## 3. 整数的表示

### 3.1 无符号整数

n 位无符号整数直接按二进制位权解释：

```text
范围：0 ~ 2^n-1
```

常用于地址、指针和明确不会出现负数的计数。

### 3.2 有符号整数

现代计算机通常用补码表示有符号整数。n 位范围：

```text
-2^(n-1) ~ 2^(n-1)-1
```

与无符号数相比，最高位既参与数值表示，也起符号作用。

| 8位机器数 | 按 unsigned 解释 | 按补码 signed 解释 |
| --- | ---: | ---: |
| `01111111` | 127 | 127 |
| `10000000` | 128 | -128 |
| `11111111` | 255 | -1 |

同一位串不变，仅解释方式不同，真值就可能不同。

## 4. C 语言整数类型与转换

### 4.1 常见整数类型

教材按常见平台口径：

| 类型 | 常见位数 |
| --- | ---: |
| `char` | 8 |
| `short` | 16 |
| `int` | 32 |
| `long` | 32 位系统常为32；64位系统依平台而定 |
| `long long` | 通常64 |

`signed` 类型通常按补码解释，`unsigned` 按无符号数解释。具体长度由编译器与目标平台决定，做题以题设为准。

### 4.2 位扩展

短类型转换为长类型：

- 无符号数：高位补 0，称零扩展。
- 补码有符号数：高位复制原符号位，称符号扩展。

```text
8位 signed：  1000 0001 (-127)
扩成16位：1111 1111 1000 0001 (-127)

8位 unsigned：1000 0001 (129)
扩成16位：0000 0000 1000 0001 (129)
```

### 4.3 位截断

长类型转短类型时直接保留低位、丢弃高位。若原真值超出目标类型范围，真值将改变。

截断后的结果必须按**目标类型**重新解释，不能沿用原类型的符号和真值。

### 4.4 同字长 signed 与 unsigned 转换

转换通常不改变位串，只改变解释方式，可按模 `2^n` 理解：

```text
signed -> unsigned：若原值 x<0，新值为 x+2^n
unsigned -> signed：若最高位为0，值不变；若最高位为1，新值为 u-2^n
```

例：32 位 `int si=-32767` 转为 `unsigned int`：

```text
ui = 2^32 - 32767
```

### 4.5 C 表达式中的隐式转换

有符号数和同级别无符号数混合运算、比较时，有符号数通常会先转换为无符号数。因此：

```c
int x = -1;
unsigned int y = 1;
```

表达式 `x < y` 在常见 32 位规则下为假，因为 `x` 转成了 `2^32-1`。

> [!warning] 机器位串相同，不等于数值相同
> C 类型转换题要依次判断：位宽是否变化、如何扩展或截断、最后按 signed 还是 unsigned 解释。

## 5. 解题模板

### 5.1 真值求机器码

```text
1. 明确总位数和小数点位置
2. 判断整数还是小数、有无符号
3. 正数：原反补相同
4. 负数：先写绝对值原码，再按规则求反码/补码
5. 若求移码，在同位宽补码基础上翻转最高位
6. 检查是否超出表示范围
```

### 5.2 机器码求真值

```text
1. 先确认编码种类，不能见最高位1就直接判负
2. 原码：符号位 + 绝对值
3. 反码：负数数值位取反
4. 补码：按权展开或求补得到绝对值
5. 移码：无符号值减偏置值
```

### 5.3 C 类型转换

```text
原值 -> 写出源类型位串 -> 扩展/截断 -> 按目标类型解释
```

## 高频易错点

- [ ] 二进制小数分组时方向错误
- [ ] 把所有有限十进制小数都当作有限二进制小数
- [ ] 机器字长为 n 位，却误按 n 位数值位再加符号位
- [ ] 负数补码只对数值位取反加一，造成位数错误
- [ ] 认为补码范围关于 0 对称
- [ ] 认为补码 `100...0` 求负后能得到可表示的正数
- [ ] 把移码偏置 `2^(k-1)` 与 IEEE 754 偏置 `2^(k-1)-1` 混淆
- [ ] 认为 signed 转 unsigned 会改写每个二进制位
- [ ] 有符号扩展时高位一律补 0
- [ ] 截断后仍按源类型解释低位
- [ ] 忽略 C 混合运算中的无符号提升

## 一页背诵版

```text
整数转r进制：除r取余，倒序
小数转r进制：乘r取整，正序
二进制<->八进制：3位一组
二进制<->十六进制：4位一组

n位unsigned：0 ~ 2^n-1
n位补码：-2^(n-1) ~ 2^(n-1)-1

原码：符号 + 绝对值
反码：负数原码数值位取反
补码：负数按位取反加1；0唯一；符号位参与运算
移码：补码最高位取反；便于比较阶码

无符号扩展：补0
有符号补码扩展：补符号位
截断：直接保留低位，再按目标类型解释
```

## 自测

1. 将 `(123.6875)10` 转为二进制和十六进制。
2. 写出 8 位补码 `10011011` 的真值。
3. 8 位原码、反码、补码各能否表示 `-128`？
4. 写出 8 位 `-66` 的原码、反码与补码。
5. 将 8 位 signed `10000001` 扩展为 16 位。
6. 32 位 `int -1` 转为 `unsigned int` 后的值是多少？
7. 为什么移码适合比较阶码大小？

### 自测答案

1. `(1111011.1011)2 = (7B.B)16`。
2. `-101`。
3. 原码和反码不能，8 位补码能表示 `-128`。
4. 原码 `11000010`，反码 `10111101`，补码 `10111110`。
5. `11111111 10000001`。
6. `2^32-1`。
7. 同位宽移码按无符号顺序比较时，编码大小顺序与真值一致。
